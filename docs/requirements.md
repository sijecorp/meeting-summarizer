# 요구사항

- 상태: v1 기준선 (2026-10-13)
- 근거: [설계 문서](designs/meeting-summarizer.md) (APPROVED)
- 관련 문서: [아키텍처](architecture.md) · [로드맵](roadmap.md)

설계 문서는 "왜 이렇게 정했는가"를 기록한다. 이 문서는 "무엇을 만드는가"를 검증 가능한 항목으로 나열한다. 둘이 어긋나면 설계 문서를 먼저 고친 뒤 이 문서를 맞춘다.

## 1. 개요

회의를 녹음하고, 로컬 Whisper로 전사하고, LLM으로 요약해 Slack으로 보내는 Windows/macOS 데스크톱 앱이다.

| 역할 | 하는 일 |
|---|---|
| 녹음자 | 회의 참석자 중 한 명. 녹음을 시작·종료하고, 요약을 검토해 Slack으로 보낸다 |
| 읽는 사람 | 회의 불참자, 나중에 합류한 사람. 앱을 쓰지 않고 Slack 메시지만 읽는다 |
| 관리자 | LLM API 키와 Slack 웹훅 URL을 만들어 녹음자에게 전달한다. 전달 방법은 설계 문서 Open Question 3 |

## 2. 범위

### v1에 포함

- 마이크 + 시스템 오디오 동시 녹음 (녹음이 끝난 뒤 처리)
- 로컬 Whisper 전사 (한국어 고정)
- 클라우드 LLM 요약(기본) + 로컬 LLM 요약(옵션), 둘 다 OpenAI 호환 API
- 검토 후 Slack 웹훅 전송
- macOS 14.6+ (**Apple Silicon 전용**), Windows 10/11 x64

### v1에서 제외

| 항목 | 이유 |
|---|---|
| 실시간 자막 | 전제 2. 읽는 사람은 회의가 끝난 뒤 요약을 읽는다 |
| 화자 분리 | 기준선이 "기록 없음"이라 없어도 가치가 있다 |
| Intel Mac | 빌드 매트릭스가 arm64뿐이다. 지원 여부는 설계 문서 Open Question 7에서 정한다 |
| Linux, 모바일 | 사내 PC가 macOS와 Windows뿐이다 |
| 다크 모드 | 회사 색상 팔레트에 다크 토큰이 없다 |
| Notion 등 다른 공유 채널 | 공유 방식은 Slack 웹훅으로 정했다 |
| 서버, 계정, 텔레메트리 | 모든 데이터는 녹음자 PC에 있다. 회의 데이터 중 외부로 나가는 것은 LLM 요청과 Slack 메시지뿐이다(모델 다운로드는 NFR-08 참고) |
| 자동 업데이트 | 파일럿 규모에서는 새 설치 파일을 사내 채널로 나눠 덮어 설치하면 된다. 공개 releases 저장소와 업데이터 서명 키가 필요해 파일럿 뒤로 미뤘다(eng review D2) |
| 설정 파일 가져오기 | 평문 비밀값 파일이 생기고 파일 형식을 유지보수해야 한다. 파일럿은 직접 입력으로 충분하다(eng review D3) |
| 텍스트 수준 에코 제거 | v1은 게이팅으로 대응한다. 스파이크 S4가 실패할 때만 v1에 넣는다 |

## 3. 기능 요구사항

우선순위: **P0** = v1 필수, **P1** = v1에 넣되 일정이 밀리면 뒤로 미룰 수 있음.

### 3.1 녹음 (REC)

| ID | 우선 | 요구사항 |
|---|---|---|
| REC-01 | P0 | 녹음 시작 버튼 한 번으로 마이크와 시스템 오디오를 동시에 녹음한다. 녹음은 한 번에 하나만 할 수 있다 |
| REC-02 | P0 | 각 트랙을 16kHz 모노 16-bit PCM WAV로 녹음하는 동안 디스크에 기록한다. 5초마다 WAV 헤더를 갱신해, 강제 종료 시 손실이 최대 5초가 되게 한다 |
| REC-03 | P0 | 두 트랙을 장치와 무관한 단조 시계에 맞춘다. 뒤처진 트랙에는 무음을 채우고, 앞선 트랙은 10초마다 넘친 샘플을 버린다. 4시간 녹음 동안 두 트랙의 시간 차이는 0.5초 이하다 |
| REC-04 | P0 | 최대 녹음 길이는 4시간이다. 3시간 50분에 경고하고, 4시간이 되면 자동으로 종료해 처리 대기열에 넣는다 |
| REC-05 | P1 | 두 트랙이 모두 15분 연속 무음(RMS -50 dBFS 미만)이면 "녹음을 계속할까요?" 알림을 띄운다. 응답이 없으면 계속 녹음하고, REC-04의 4시간 상한에서 끝난다 |
| REC-06 | P0 | 녹음 중에는 시스템 절전을 막는다. 그래도 절전되면, 5분 이하일 때는 깨어난 뒤 이어서 녹음하고, 5분을 넘으면 절전 시점에서 녹음을 끝내 대기열에 넣은 뒤 깨어날 때 알린다 |
| REC-07 | P0 | 장치가 분리되면 2초 안에 새 기본 장치로 다시 연결한다. 대체할 장치가 없으면 그 트랙을 무음으로 채우며 녹음을 계속하고 알린다. 1초마다 OS 기본 입력·출력 장치를 확인해, 바뀌었으면(예: 헤드셋 연결) 오류가 없어도 다시 연결한다. 설정에서 고정한 장치가 사라지면 기본 장치로 바꾼다. 어느 경우든 화면에 경고 배너를 띄운다 |
| REC-08 | P0 | 녹음 시작 후 3초 동안 마이크 트랙이 완전한 0이면 권한 경고 배너를 띄운다(닫을 수 있음). 시스템 오디오는 녹음 중에 경고하지 않는다 |
| REC-09 | P0 | 녹음 중 화면에 경과 시간과 트랙별 스펙트럼(마이크, 시스템 오디오)을 보여준다. 스펙트럼은 장식이라 화면 읽기 프로그램에는 트랙별 음량을 따로 알려 준다 |
| REC-10 | P1 | 헤드폰 권장 안내를 두 곳에 띄운다. 설정의 오디오 탭, 그리고 녹음 중 시스템 오디오가 감지됐을 때 녹음 화면의 작은 문구다 |
| REC-11 | P0 | 시작 전 여유 공간이 1.5GB 미만이면 녹음 가능 시간을 경고한다. 녹음 중 60초마다 확인해 200MB 미만이거나 쓰기 오류가 나면 그때까지를 안전하게 저장하고 처리 대기열에 넣은 뒤 알린다([아키텍처 4.6](architecture.md#46-디스크-공간-rec-11-eng-review-d7)) |

### 3.2 전사 (TRN)

| ID | 우선 | 요구사항 |
|---|---|---|
| TRN-01 | P0 | 녹음이 끝나면 회의를 처리 대기열에 자동으로 넣는다. 전사는 한 번에 최대 2개 회의까지 하고, 나머지는 들어온 순서(FIFO)대로 대기열에서 기다리며 "대기 중"과 대기 순서를 보여 준다. 사용자 결정(2026-10-14). 동시에 2개를 전사하면 메모리 사용이 두 배가 되어 8GB 기기에서 부족할 수 있다. 파일럿에서 지켜볼 위험이다 |
| TRN-02 | P0 | 두 트랙을 합산할 때 게이팅을 적용한다. 시스템 오디오에 소리가 있는 동안 마이크 트랙을 낮춘다(기본 -20dB, S4에서 조정) |
| TRN-03 | P0 | VAD로 찾은 무음 지점에서 약 10분 단위로 잘라 순서대로 전사한다. 구간이 끝날 때마다 결과를 저장한다 |
| TRN-04 | P0 | 전사 파라미터: `language=ko`, Silero VAD, `no_context`, `suppress_nst` |
| TRN-05 | P0 | 백엔드 설정은 자동 / GPU / CPU다. 자동일 때 macOS는 Metal, Windows는 Vulkan을 쓰고, Vulkan 장치가 없거나 초기화에 실패하면 CPU로 바꾼다 |
| TRN-06 | P0 | 전사는 자식 프로세스(같은 실행 파일의 워커 모드)에서 돈다. GPU 워커가 비정상 종료하면 같은 구간을 GPU로 한 번 더 즉시 시도하고, 다시 비정상 종료하면 "GPU 실패"를 기록해 이후 자동 모드는 CPU를 쓰고 녹음자에게 알린다. 앱 재시작은 필요 없다. 정상 종료로 멈춘 처리는 `paused`로 기록한다 |
| TRN-07 | P1 | 구간 결과가 비정상이면(음성 구간인데 빈 전사, 같은 토큰이 연속으로 반복) 그 구간을 CPU로 다시 처리한다 |
| TRN-08 | P0 | 환각 필터는 세그먼트 전체 텍스트(공백·문장부호 정규화 후)가 목록 문구와 **정확히 일치할 때만** 제거한다. 목록은 앱 리소스 파일로 관리한다 |
| TRN-09 | P0 | 녹음이 시작되면 실행 중인 전사 워커 프로세스를 모두 즉시 종료한다. 녹음이 끝나면 각 회의의 그 구간을 처음부터 다시 처리한다 |
| TRN-10 | P1 | 용어집(사람 이름, 제품명, 최대 100개)을 설정에서 관리한다. 요약 프롬프트에 넣는다. Whisper initial prompt에도 넣을지는 S2 결과로 정한다 |

### 3.3 요약 (SUM)

| ID | 우선 | 요구사항 |
|---|---|---|
| SUM-01 | P0 | OpenAI 호환 Chat Completions API로 요약한다. 연결 정보는 `base_url`, `api_key`, `model` 세 가지다. 클라우드 공급자와 로컬 Ollama·LM Studio를 같은 코드로 처리한다 |
| SUM-02 | P0 | 출력 형식은 고정이다: 제목 / 결정사항 / 액션 아이템(담당자·기한) / 주요 논의 / 미해결 질문 |
| SUM-03 | P0 | 발화에 명시되지 않은 담당자나 기한은 "미정"으로 쓴다. 추정하지 않는다 |
| SUM-04 | P0 | 전사본이 설정된 컨텍스트 한도를 넘으면 구간별로 요약한 뒤 합친다 |
| SUM-05 | P0 | LLM이 만든 원본 요약을 `summary.generated.md`로 따로 저장한다 |
| SUM-06 | P0 | 요약이 실패하면(네트워크, 키 미설정·만료, 할당량 초과, 로컬 LLM 미실행, 긴 회의의 구간 일부 실패) 전사본을 보존하고, 원인과 "요약 다시 실행"을 보여준다. 다시 실행할 때 다른 LLM 설정을 고를 수 있다 |
| SUM-07 | P0 | 클라우드 LLM으로 전사본이 나간다는 사실을 설정·녹음 중·처리 중 화면에 공급자 이름과 함께 표시한다. 검토 화면에는 "{공급자}로 전송됨"으로 표시한다 |
| SUM-08 | P0 | 로컬 LLM이 설정돼 있으면 녹음 중·처리 중 화면에 "로컬로 요약" 토글을 둔다. 요약이 시작되기 전까지 바꿀 수 있고, 기본값은 설정값이다. 로컬 연결이 여러 개면 기본 연결이 로컬일 때 그것을, 아니면 첫 번째 로컬 연결을 쓴다 |
| SUM-09 | P0 | 녹음이 시작되면 진행 중인 로컬 LLM 요약을 중단하고, 녹음이 끝나면 다시 실행한다. 클라우드 요약은 계속 진행한다 |
| SUM-10 | P0 | 환각 필터를 거친 전사본이 30자 미만이면 LLM을 부르지 않는다. 검토 화면에 "음성이 거의 감지되지 않았습니다"를 보여주고 전송 버튼을 비활성화한다 |

### 3.4 검토 (REV)

| ID | 우선 | 요구사항 |
|---|---|---|
| REV-01 | P0 | 제목과 요약을 편집할 수 있다. "미정" 항목을 강조한다. 원문 전사본을 함께 볼 수 있다. |
| REV-02 | P0 | 전송될 글자 수(머리말·본문 포함, 꼬리말은 별도 블록이라 제외)를 보여준다. 12,000자를 넘으면 전송 버튼을 비활성화하고 줄이라고 안내한다 |
| REV-03 | P0 | "전송 안 함"을 누르면 `archived`가 되어 미전송 목록에서 빠진다 |
| REV-04 | P0 | 어느 상태의 회의든 삭제할 수 있다. 확인 후, 진행 중인 녹음·전사·요약을 먼저 취소하고 멈춘 것을 확인한 뒤 폴더를 지운다. 늦게 도착한 결과는 버린다([아키텍처 8.3](architecture.md#83-상태-전이)) |
| REV-05 | P1 | 전사본과 요약을 클립보드로 복사하거나 `.md` 파일로 저장할 수 있다 |

### 3.5 Slack 전송 (SND)

| ID | 우선 | 요구사항 |
|---|---|---|
| SND-01 | P0 | Slack Incoming Webhook으로 보낸다. 본문은 `markdown` 블록이다. 웹훅이 이 블록을 거부하면(400 `invalid_blocks`) mrkdwn `section` 블록으로 변환해 자동으로 한 번 다시 보낸다(M5, [아키텍처 7.1](architecture.md#71-페이로드)). 스파이크 S5는 실제 Slack이 어느 쪽으로 가는지 확인한다 |
| SND-02 | P0 | 머리말: 제목, 일시, 녹음 길이, 녹음자 이름. 일시는 녹음자 현지 시각의 회의 시작(예: `2026-10-13 (화) 14:00`)이고, 녹음자 이름이 비어 있으면 뺀다 |
| SND-03 | P0 | 꼬리말: "AI 요약 · 녹음자 검토 완료 (수정 N곳)". N은 `summary.generated.md`와 전송본을 줄 단위로 비교해 추가·삭제·변경된 줄 수다. 제목을 바꿨으면 1을 더한다 |
| SND-04 | P0 | 웹훅은 이름을 붙여 여러 개 저장한다. 기본 채널은 다음 순서로 정한다: 웹훅이 1개면 그것, 이전에 보낸 적이 있으면 마지막 채널, 처음이면 목록의 첫 번째. 전송 버튼에 채널 이름을 표시한다(예: "#회의록으로 전송") |
| SND-05 | P0 | 녹음자가 전송 버튼을 누르기 전에는 절대 보내지 않는다 |
| SND-06 | P0 | 전송에 실패하면 원인을 보여주고, 다시 보내기와 클립보드 복사를 제공한다. 자동으로 다시 보내지 않는다(응답만 잃었으면 두 번 올라간다). 실패한 회의는 `review`에 남고 원인은 다음에 열 때도 보인다 |

### 3.6 저장과 복구 (STO)

| ID | 우선 | 요구사항 |
|---|---|---|
| STO-01 | P0 | 회의마다 앱 데이터 폴더 아래 `meetings/{id}/`에 저장한다. DB는 쓰지 않는다 |
| STO-02 | P0 | 상태(`recording` → `recorded` → `transcribing` → `transcribed` → `summarizing` → `review` → `sent` 또는 `archived`, 그리고 각 단계의 실패 상태, `paused`, 삭제 중인 `deleting`)를 `meta.json`에 기록한다 |
| STO-03 | P0 | 앱이 시작될 때 `recording`으로 남은 회의는 "중단된 녹음"으로 보여주고 "처리 계속 / 삭제"를 제안한다. 처리 중 멈춘 회의는 마지막으로 끝난 구간부터 이어서 처리한다 |
| STO-04 | P0 | 오디오와 결과물은 녹음자가 회의를 삭제할 때까지 보관한다. 보관 정책(설계 문서 Open Question 5)이 정해지면 바꾼다 |
| STO-05 | P0 | `meta.json`과 `settings.json`에 `schema_version`을 둔다. 더 높은 버전의 데이터는 읽기 전용으로 열고 안내한다. 낮은 버전은 읽을 때 옮긴다 |

### 3.7 앱 동작 (APP)

| ID | 우선 | 요구사항 |
|---|---|---|

### 3.8 첫 설정과 설정 (ONB)

온보딩 화면은 두지 않는다(사용자 결정 2026-10-14). 앱은 항상 홈으로 열린다. 빠진 설정이 있으면 홈 맨 위의 설정 카드가 항목마다 한 줄로 보여 주고, 버튼을 누르면 그 항목이 있는 설정 탭이 열린다. 녹음은 설정이 없어도 바로 할 수 있다.

| ID | 우선 | 요구사항 |
|---|---|---|
| ONB-01 | P0 | 첫 실행 때 Whisper 모델과 VAD 모델을 내려받는다. 진행률, 이어받기, sha256 검증을 한다. URL과 해시는 [아키텍처 5.1](architecture.md#51-모델-파일)에 고정한다 |
| ONB-02 | P0 | 다운로드가 실패하면 "모델 파일 직접 가져오기"를 제공한다. 녹음자가 고른 파일의 해시를 검증한 뒤 설치한다. 설정에서 다운로드 기준 URL을 사내 미러로 바꿀 수 있다 |
| ONB-03 | P0 | 설정의 오디오 탭에 시스템 오디오 테스트(테스트음을 재생하고 루프백에 잡히는지 확인)와 입력 레벨 미터를 둔다. 마이크 권한은 첫 녹음 때 OS가 묻는다([아키텍처 4.4](architecture.md#44-권한-감지-rec-08)). 알림: 데스크톱의 알림 권한 API는 항상 허용으로 응답해 거부를 감지할 수 없으므로, 설정의 일반 탭에 "알림이 보이지 않으면 OS 알림 설정에서 '회의 요약'을 허용해 주세요"를 두고 트레이 표시를 항상 보조 경로로 둔다 |
| ONB-04 | P0 | 연결 설정은 직접 입력한다: LLM 연결(이름, `base_url`, 모델, API 키)과 Slack 웹훅(이름, URL). 비밀값은 설정을 저장할 때 OS 키체인에 넣는다([아키텍처 9.2](architecture.md#92-키체인)) |
| ONB-05 | P0 | 녹음자 이름은 OS 사용자 이름을 기본값으로 하고, 설정의 일반 탭에서 고칠 수 있다 |
| ONB-06 | P0 | 설정의 Slack 탭에서 선택한 웹훅으로 테스트 메시지를 보낸다 |
| ONB-07 | P0 | 설정 화면은 왼쪽 탭으로 나눈다: 일반(녹음자 이름), 오디오(마이크, Windows만 시스템 오디오 출력 장치), 전사(모델, 전사 백엔드, 용어집, 모델 다운로드 URL은 M3), 요약(LLM)(LLM 연결 여러 개, 기본 LLM), Slack(웹훅). 저장 버튼 하나가 모든 탭을 함께 저장한다 |
| ONB-08 | P0 | API 키와 웹훅 URL은 OS 키체인(macOS Keychain, Windows Credential Manager)에만 저장한다 |

## 5. 성공 지표

설계 문서의 Success Criteria를 따른다. 지표를 해석할 때 주의할 점이 두 가지 있다.

- **주 지표(전송 비율)와 보조 지표(수정 N곳)는 모두 Slack 채널에서 집계한다.** 각 PC에서 파일을 모을 필요가 없다.
- **수정 수가 적다고 요약이 정확하다는 뜻은 아니다.** 녹음자가 검토 없이 보냈을 수도 있다. 그래서 파일럿 2주차와 4주차에 한 번씩, 실제 불참자 1명에게 결정사항과 본인 할 일을 맞게 말할 수 있는지 확인한다([로드맵 M7](roadmap.md#m7-파일럿)).
