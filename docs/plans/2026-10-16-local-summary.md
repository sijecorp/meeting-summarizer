# 계획: 로컬 요약을 기본으로 (M6.5)

- 상태: 초안 (2026-10-16), 계획 리뷰 전
- 관련: [요구사항](../requirements.md), [아키텍처 5·6·8](../architecture.md), [로드맵](../roadmap.md)

## 1. 왜

파일럿(M7) 전에 요약 경로를 바꾼다. 지금은 클라우드 LLM 요약이 기본이고(요구사항 2, SUM-01), 로컬 LLM은 녹음자가 Ollama나 LM Studio를 직접 설치하고 연결 주소와 컨텍스트 길이까지 맞춰야 쓸 수 있다. 사용자 판단(2026-10-16): 상위 클라우드 모델은 API 비용이 청구되므로, 가벼운 로컬 LLM으로 요약하는 것을 기본으로 한다.

함께 다룰 요청: 앱을 지웠다가 새 버전을 설치했을 때, PC에 남아 있는 모델과 로컬 LLM을 찾아 그대로 쓴다.

## 2. 사용자 결정 (2026-10-16)

| 질문 | 결정 |
|---|---|
| 로컬 LLM 실행 방식 | **앱에 내장**: llama.cpp의 `llama-server`를 앱과 함께 배포하고, 요약 모델은 첫 실행 때 전사 모델처럼 내려받는다. 동료가 따로 설치할 것은 없다 |
| 이미 있는 로컬 LLM 찾기 | **앱이 받은 모델 재사용 + 실행 중인 Ollama·LM Studio 찾기** |
| 클라우드 연결 | **선택 사항으로 남긴다**. 기본은 로컬, 원하는 사람만 클라우드 연결을 추가한다 |
| 요약 모델 | **Qwen3.5-4B로 바로 시작**. 비교 평가 없이 시작하고 품질은 파일럿에서 본다. 나중에 바꿀 수 있게 모델은 표 한 곳에서 정한다 |

## 3. 조사 요약

근거와 출처는 이 계획의 리뷰 기록과 함께 남긴다. 숫자 중 속도는 공개 7B 벤치마크에서 옮겨 잡은 추정이다.

- **모델**: Qwen3.5-4B(Apache-2.0, 2026-03). GGUF는 `unsloth/Qwen3.5-4B-GGUF`의 `Qwen3.5-4B-Q4_K_M.gguf`(2.74GB). 같은 크기대의 Gemma 4 E4B(Apache-2.0)는 파일이 더 크고, Kanana-1.5-8B(Apache-2.0)는 한국어 근거가 가장 분명하지만 약 5GB에 컨텍스트 32k다. EXAONE 4.x는 상업 목적 사용 금지라 쓰지 않는다. HyperCLOVA X SEED는 쓸 수는 있으나 조건이 많다.
- **실행 방식**: llama.cpp를 Rust 크레이트로 앱 안에 넣으면 whisper-rs가 이미 정적으로 넣은 ggml과 심볼이 겹친다(rust-lang 포럼 LNK2005, whisper-rs #194). 전사 워커처럼 같은 실행 파일을 다시 띄우는 방식도 같은 바이너리라 피하지 못한다. 별도 바이너리인 `llama-server`는 OpenAI 호환 `/v1/chat/completions`와 `usage`를 주므로 `summarize.rs`를 거의 그대로 쓴다. 컨텍스트는 실행 인자 `-c`로 앱이 정하므로, 지금 Ollama에서 생기는 "서버가 입력을 말없이 자름" 문제가 내장 경로에서는 없어진다.
- **속도 추정** (1시간 회의, 약 2만 토큰, 4B Q4): M1~M3 Mac 2~4분, Windows 내장 GPU(Vulkan) 3~10분, Windows CPU만 8~15분.
- **재설치**: 앱이 받은 모델은 `app_local_data_dir/models`에 있고, macOS에서 앱을 휴지통에 넣거나 Windows에서 "애플리케이션 데이터 삭제하기"를 고르지 않고 지우면 남는다. 다시 설치하면 크기 확인만으로 그대로 쓴다(지금 전사 모델이 이미 그렇다). Windows에서 그 상자를 고르면 모델·회의·설정이 함께 지워진다(사용자가 고른 삭제라 그대로 둔다).
- **로컬 서버 감지**: 지금은 없다. `local_available`은 설정에 `is_local` 연결이 있는지만 본다.

## 4. 목표와 끝 조건

- 새로 설치한 앱은 설정 없이 녹음 → 전사 → **이 PC에서 요약** → 검토 → Slack 전송까지 된다. 필요한 것은 Slack 웹훅뿐이다.
- 요약 모델을 받은 PC는 앱을 다시 설치해도 다시 받지 않는다.
- 요약(LLM) 탭의 "이 PC의 로컬 LLM 찾기"가 실행 중인 Ollama·LM Studio와 그 모델을 보여 주고, 고르면 연결이 추가된다.
- 클라우드 연결은 지금처럼 추가해 쓸 수 있다. 기본 경로는 아니다.
- M1 Mac에서 1시간 회의의 내장 요약이 5분 안에 끝난다(NFR-01을 로컬 기준으로 다시 정한다. Windows 목표는 실측 뒤 정한다).
- 내장 요약 중 녹음을 시작하면 요약이 멈추고 CPU·GPU를 내준다(SUM-09).

**범위 밖**: 모델 비교 평가(파일럿 뒤), 여러 로컬 모델 중 고르기 UI(표 한 곳만 둔다), Apple Foundation Models, 앱 안 Ollama 설치, 자동 업데이트.

## 5. 설계

### 5.1 내장 런타임: `llama-server` 사이드카
- llama.cpp를 커밋 하나로 고정하고, CI에서 소스를 **정적 링크**(`BUILD_SHARED_LIBS=OFF`)로 빌드해 실행 파일 하나로 만든다. macOS arm64는 Metal(`GGML_METAL_EMBED_LIBRARY`), Windows x64는 Vulkan(이미 CI에 Vulkan SDK가 있다). 릴리스 zip을 쓰지 않는 이유: 공식 빌드는 `libllama`·`libggml*` 공유 라이브러리를 함께 두어야 하는데, Tauri `externalBin`은 실행 파일 하나만 다룬다.
- Tauri `bundle.externalBin`(`binaries/llama-server-<target-triple>`)로 넣는다. macOS에서는 번들러가 함께 ad-hoc 서명한다. 로컬 개발용으로 같은 빌드를 하는 스크립트(`scripts/build-llama-server.sh`, `.ps1`)를 두고 결과물은 git에 넣지 않는다.
- 크기: 약 10~40MB 늘어난다(추정, 빌드 후 확인).
- 라이선스: llama.cpp MIT, Qwen3.5 Apache-2.0을 `THIRD_PARTY_NOTICES.md`에 더한다.

### 5.2 요약 모델 파일
- 전사 모델과 같은 표(`transcribe/model.rs`의 파일 표, 또는 공용 모듈로 옮김)에 요약 모델 한 줄을 더한다: 저장소, 파일, 크기, sha256. 같은 받기 코드(이어받기, 해시 확인, 사내 미러 `model_base_url`, 직접 가져오기)를 쓴다.
- 받는 시점: 전사 모델과 따로 받는다. 홈 설정 줄에 "요약 모델 받기"를 더하고, 요약(LLM) 탭 맨 위에서도 받는다. 모델이 없으면 내장 경로는 "요약 모델이 없습니다"로 회의를 `transcribed`에 남긴다(지금 LLM 연결이 없을 때와 같다).
- 재설치 재사용: 위치가 같은 `models` 폴더라 그대로 된다. 테스트로 고정한다.

### 5.3 사이드카 수명
- **늦게 띄운다**: 첫 내장 요약 작업이 시작될 때 띄운다. 앱을 열 때 띄우지 않는다(약 3~5GB 메모리).
- 인자: `-m <모델> -c <컨텍스트> --host 127.0.0.1 --port <빈 포트> --parallel 1 --api-key <실행마다 새 난수> -ngl 99 --no-webui`. API 키로 같은 PC의 다른 프로세스가 이 서버를 쓰지 못하게 한다. 포트는 `127.0.0.1:0`에 바인드해 얻는다.
- 준비 확인: `/health`가 200이 될 때까지 기다린다(모델 불러오기, 상한을 둔다).
- 멈춤: 큐가 빈 뒤 일정 시간(예: 5분) 쓰지 않으면 끝낸다. 앱 종료, 녹음 시작(SUM-09)에도 끝낸다. 녹음 시작 때 요청만 끊으면 서버가 계속 생성하므로 프로세스를 끝내는 쪽이 확실하다. 다시 필요하면 다시 띄운다.
- GPU 실패: 서버가 시작 중 죽거나 GPU 오류로 끝나면 `-ngl 0`(CPU)으로 한 번 다시 띄우고, 전사의 `gpu_failed`처럼 기록해 다음부터 CPU로 띄운다.
- 생각 모드 끄기: 요청 본문에 `chat_template_kwargs: {"enable_thinking": false}`를 보낸다. 지금의 `<think>` 걷어내기는 그대로 둔다.

### 5.4 연결 모델과 경로 선택
- 내장 경로를 "연결" 하나로 다룬다: 이름 "이 PC", `is_local=true`, 주소는 실행 때 정해진다. 설정 파일에는 저장하지 않는 고정 연결로 두고, `llm_connections`에는 사용자가 추가한 연결(Ollama, LM Studio, 클라우드)만 남긴다. `default_llm`이 비어 있으면 내장 경로다.
- 경로 선택(아키텍처 6.1) 순서: 회의에 고정된 연결 → "로컬로 요약"이면 로컬 기본(기본 연결이 로컬이면 그것, 아니면 내장) → 기본 연결 → 내장.
- "로컬로 요약" 토글(SUM-08): 내장 경로가 늘 있으므로 기본 연결이 클라우드일 때만 의미가 있다. 기본이 로컬이면 토글을 숨긴다.
- 기존 설치의 이전(migration): `default_llm`이 클라우드인 기존 설정은 그대로 두고, 요약(LLM) 탭에 "이 PC에서 요약하기로 바꾸기"를 한 줄 둔다. 파일럿 전이라 기존 사용자는 개발자뿐이다(리뷰에서 다시 본다).

### 5.5 큐와 자원
- 16GB PC에서 whisper 워커 둘(각각 CPU 절반)과 4B 모델이 겹치면 메모리와 GPU가 모자란다. 규칙: **내장 요약은 한 번에 하나, 그동안 새 전사는 시작하지 않는다.** 이미 돌고 있는 전사는 끝나기를 기다린 뒤 요약을 시작한다. 클라우드·외부 로컬 연결은 지금 규칙 그대로다.
- 녹음 중에는 지금처럼 새 작업을 시작하지 않고, 진행 중인 내장 요약은 5.3처럼 멈춘 뒤 녹음이 끝나면 처음부터 다시 한다(부분 요약은 저장하지 않는 지금 방식 유지).

### 5.6 요약 파이프라인 조정
- 내장 경로의 `context_tokens` 기본값은 16,384로 둔다(메모리와 속도의 절충, 실측 뒤 조정). 서버를 같은 값으로 띄우므로 입력 잘림 감지는 외부 연결에만 남는다.
- 프롬프트는 지금 것을 쓰고, 작은 모델이 형식을 어기는 경우(섹션 빠짐, 담당자 지어냄)는 파일럿에서 모은다. 출력 형식 강제(JSON 스키마·문법)는 이번 범위에 넣지 않는다.
- 시간 제한: 내장 경로는 로컬 기본값(900초)을 쓴다.

### 5.7 이미 있는 로컬 LLM 찾기
- 요약(LLM) 탭의 "이 PC의 로컬 LLM 찾기" 버튼: `127.0.0.1:11434`(Ollama `/api/tags`)와 `127.0.0.1:1234`(LM Studio `/v1/models`)를 짧은 시간 제한으로 묻고, 응답한 서버의 모델 목록을 보인다. 고르면 연결(이름, `base_url` `/v1`, 모델, `is_local=true`)이 저장할 변경으로 추가된다.
- Ollama 연결의 `context_tokens`는 서버 기본값과 맞게 4,096으로 넣고, 도움말로 늘리는 법을 안내한다(지금의 입력 잘림 감지가 그대로 지킨다).
- 앱을 열 때 자동으로 묻지 않는다(버튼을 누를 때만). 디스크의 Ollama·LM Studio 모델 파일을 직접 읽어 내장 서버로 쓰는 것은 하지 않는다(경로·형식이 버전마다 다르다).

### 5.8 화면
- 요약(LLM) 탭: 맨 위 묶음 "이 PC에서 요약 (기본)": 모델 상태(받기·진행 막대·취소·직접 가져오기), 처리 장치(GPU/CPU), 메모리 안내 한 줄. 아래 묶음 "다른 연결": 지금의 연결 목록 + "이 PC의 로컬 LLM 찾기". 기본 LLM 선택에 "이 PC"가 들어간다.
- 홈 설정 줄: "요약 모델 받기"(받는 중이면 %).
- 요약 경로 안내(SUM-07): 내장이면 "이 PC에서 요약합니다", 클라우드 고지는 클라우드 연결일 때만.
- 디자인 시스템 3판 규칙(세리프는 포인트만, em dash 금지)을 따른다.

### 5.9 문서·요구사항 고칠 곳

## 7. 위험과 열린 질문

- **요약 품질**: 4B 모델의 한국어 회의 요약은 검증된 근거가 없다. 특히 담당자·기한을 지어내는 것이 가장 큰 위험이다. 파일럿에서 수정 횟수(REV)로 본다.
- **Windows 속도와 메모리**: CPU만 있는 PC는 1시간 회의에 10분 넘게 걸릴 수 있다. 느린 PC 안내와 클라우드 연결 안내를 둘지 리뷰에서 정한다.
- **정적 빌드**: llama.cpp를 정적 링크한 `llama-server`가 두 OS에서 깨끗이 빌드되는지, Windows에서 260자 경로 문제가 다시 나는지(짧은 target 경로를 같이 쓴다).
- **Qwen3.5 지원**: 고른 llama.cpp 커밋이 Qwen3.5 구조와 생각 모드 끄기를 지원하는지 1단계에서 확인한다.
- **백신 오탐**: 서명 없는 `llama-server.exe`가 Windows 백신에 걸릴 수 있다.
