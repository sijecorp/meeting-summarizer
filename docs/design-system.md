# 디자인 시스템: Paper & Pulse

- 상태: 확정 (2026-10-15). 리디자인 구현의 기준이다. 시그니처 연출 네 가지(6.2 독↔녹음 화면, 6.1 제목 공유 전환, 6.5 파이프라인·뼈대, 6.6 미정 형광펜·보내기)와 녹음 단축키, 개발용 미리보기를 모두 넣기로 했다.
- 관련: [아키텍처 10.3](architecture.md#103-색상-토큰)의 색상 토큰과 대비 규칙은 이 문서로 옮겨 온다. 접근성 규칙(NFR-09, 10.4)은 그대로 지킨다.

## 1. 방향

사용자 결정(2026-10-15): Granola의 UI/UX를 참고하되 색은 따르지 않는다. "AI가 만든 티"를 없애고, 폰트와 애니메이션을 적극적으로 써서 스타트업 제품처럼 보이게 한다. 같은 날 갱신: 제목은 Granola처럼 세리프로 한다(처음 고른 Wanted Sans는 뺐다).

| 결정 | 내용 |
|---|---|
| 폰트 | 제목·큰 숫자는 세리프(라틴·숫자 Instrument Serif, 한글 Noto Serif KR), 본문·UI Pretendard |
| 색 | 회사 `mainBlue`는 포인트에만 쓴다. 바탕은 따뜻한 종이색 중성색을 새로 둔다 |
| 구조 | 홈은 날짜별 타임라인, 검토는 테두리 없는 문서형 에디터, 녹음 상태는 어느 화면에서나 아래에 떠 있는 녹음 독 |

이름의 뜻: 바탕은 종이처럼 조용하고(Paper), 소리와 처리 상태가 있는 곳만 살아 움직인다(Pulse). 움직임은 "지금 무언가 일어나고 있다"를 알릴 때만 쓴다. 장식용 움직임은 두지 않는다.

**하지 않는 것**
- 보라·청록 그라데이션, 유리 효과(glassmorphism), 모든 것을 카드에 넣는 레이아웃. AI가 만든 UI의 전형이다.
- 카드마다 테두리와 그림자. 경계는 여백과 가는 구분선으로 만든다. 그림자는 떠 있는 층(독, 팝오버, 대화상자)에만 쓴다.
- 이모지 아이콘. 아이콘은 지금처럼 `lucide-react`만 쓴다(획 두께 1.75로 통일).

## 2. 타이포그래피

폰트 파일은 앱에 넣는다(CSP가 외부 폰트를 막는다). 세 폰트 모두 SIL OFL 1.1이라 `THIRD_PARTY_NOTICES.md`(M6)에 넣는다.

| 역할 | 폰트 | 패키지 (정확한 버전 고정) |
|---|---|---|
| Display 라틴·숫자: 화면 제목, 회의 제목, 큰 숫자 | Instrument Serif (400과 이탤릭만) | `@fontsource/instrument-serif@5.3.0` (기본 CSS + `400-italic.css`) |
| Display 한글 | Noto Serif KR Variable (굵기 200~900) | `@fontsource-variable/noto-serif-kr@5.3.0` (기본 CSS) |
| Text: 본문, UI, 레이블, 타이머 | Pretendard Variable | `pretendard@1.3.9` (`dist/web/variable/pretendardvariable-dynamic-subset.css`) |

- 세 CSS 모두 `unicode-range`로 나뉜 woff2를 쓴다. Vite가 파일을 번들에 넣고, 화면에 쓰인 글자 범위만 읽는다.
- Display는 `"Instrument Serif", "Noto Serif KR Variable", serif`다. Instrument Serif에는 한글이 없어 한글은 Noto Serif KR로 넘어간다. 크기 토큰의 굵기는 한글(Noto Serif KR) 기준이고, Instrument Serif는 한 굵기뿐이라 가짜 굵게를 만들지 않는다(`font-synthesis: style`).
- 숫자: 시간·진행률·글자 수는 `tabular-nums`로 폭을 고정한다. 바뀔 때 글자가 흔들리지 않게 하려는 것이다. Instrument Serif와 Noto Serif KR에는 고정폭 숫자(`tnum`)가 없다(번들 파일을 fontTools로 확인). 그래서 타이머처럼 바뀌는 숫자는 Pretendard 고정폭 숫자로 쓴다.
- **이탤릭 숫자**: Instrument Serif 이탤릭 숫자는 시그니처 포인트다. 큰 개수와 타임라인의 시각처럼 바뀌지 않는 숫자에 `font-display italic`으로 쓴다. 숫자만 감싼다(Noto Serif KR에는 이탤릭이 없어 한글은 기울기만 흉내 낸다).
- 대체 폰트: `"Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`.

**크기 단계** (px / 줄 높이 / 굵기 / 자간)

| 토큰 | 크기 | 줄 높이 | 굵기 | 자간 | 쓰는 곳 |
|---|---|---|---|---|---|
| `display-xl` | 80 | 1.0 | 500 | -0.02em | 녹음 화면 타이머(Pretendard 고정폭 숫자), 큰 이탤릭 숫자 |
| `display-l` | 44 | 1.2 | 600 | -0.02em | 검토 문서 제목 (세리프) |
| `display-m` | 32 | 1.25 | 600 | -0.02em | 화면 제목, 빈 화면 문구 (세리프) |
| `title` | 20 | 1.35 | 600 | -0.01em | 날짜 그룹, 섹션 제목, 워드마크 (세리프) |
| `body-doc` | 16 | 1.75 | 400 | 0 | 요약 본문, 전사본 |
| `body` | 15 | 1.55 | 400 | -0.005em | UI 기본 |
| `label` | 13 | 1.4 | 550 | 0 | 레이블, 칩, 버튼 보조 |
| `caption` | 12 | 1.4 | 500 | 0.01em | 시각, 메타 정보 |

- 세리프는 같은 크기에서 산세리프보다 작아 보여 Display 단계를 한 칸씩 키웠다(72/40/28/18 → 80/44/32/20).
- 본문 글자는 13px 미만으로 쓰지 않는다. `caption`은 시각·메타처럼 짧은 정보에만 쓴다.

## 5. 모션

라이브러리: `motion@13.4.6` (`motion/react`, MIT). 공개된 지 2주가 넘은 버전으로 고정한다.

**토큰** (`src/lib/motion.ts` 한 곳에 둔다)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `spring.snappy` | stiffness 520, damping 38 | 버튼 눌림, 스위치, 탭 표시자 |
| `spring.gentle` | stiffness 260, damping 30 | 레이아웃 이동, 공유 요소(제목이 목록에서 문서로) |
| `spring.dock` | stiffness 380, damping 28, mass 0.9 | 녹음 독 등장·형태 변화 |
| `dur.micro` / `small` / `medium` / `large` | 120 / 200 / 320 / 480ms | 색·불투명도 전환 |
| `ease.out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 들어올 때 |
| `ease.in` | `cubic-bezier(0.55, 0, 1, 0.45)` | 나갈 때. 나가는 시간은 들어오는 시간의 65% |
| `stagger` | 35ms | 목록 행 등장 |

**규칙**
- `transform`과 `opacity`만 움직인다. 너비·높이·위치 속성은 움직이지 않는다(레이아웃 흔들림 방지). 높이가 바뀌는 곳은 `layout` 애니메이션을 쓴다.
- 화면 하나에서 동시에 눈에 띄게 움직이는 요소는 1~2개다.
- 움직임은 사용자 입력을 막지 않는다. 진행 중인 애니메이션은 새 입력이 오면 그 자리에서 바뀐다.
- **움직임 줄이기**: 앱 최상단에 `<MotionConfig reducedMotion="user">`를 둔다. OS 설정이 켜져 있으면 이동·크기 변화는 끄고 불투명도 전환만 남긴다. CSS 애니메이션(파형, 반짝임)은 `motion-safe:`로만 건다.
- 테스트: `src/test-setup.ts`에서 `MotionGlobalConfig.skipAnimations = true`로 애니메이션을 건너뛴다.

## 6. 화면별 설계

### 6.1 앱 셸
- **헤더** (48px, 바탕은 `paper` 92% + 뒤 흐림, 아래 `line`): 왼쪽 워드마크 "회의 요약"(Display 세리프 `title`, 앞에 작은 파형 로고 3막대: 처리 중일 때만 움직인다), 오른쪽에 처리 표시("처리 중 2 · 대기 1", 작은 원형 진행 표시와 함께)와 설정 버튼. 녹음 상태는 헤더가 아니라 녹음 독이 보인다.
- **화면 전환**: 앞으로 가는 이동(홈 → 회의)은 새 화면이 아래 8px에서 떠오르며 나타나고(320ms), 뒤로 가는 이동은 반대로 내려간다. 회의 제목은 홈 목록과 문서 사이에서 `layoutId`로 이어져, 목록의 제목이 문서 제목 자리로 커지며 옮겨 간다.
- **배너와 알림**: 배너는 높이 `layout` 애니메이션으로 밀려 들어오고 나간다. "복사했습니다", "저장됨" 같은 짧은 확인은 버튼 옆 작은 알약으로 나타났다 사라진다(3초).

### 6.2 녹음 독 (모든 화면, 녹음 중)
화면 아래 가운데 떠 있는 `dock` 색 알약(높이 56px, `float` 그림자).
```
╭──────────────────────────────────╮
│ ● ▁▃▆█▆▃▁▂▅▇▅▂  12:34   [■ 종료] │
╰──────────────────────────────────╯
```
- "로컬로 요약" 스위치와 전송 고지는 독에 넣지 않고 녹음 화면에 둔다. 독은 상태와 종료만 맡는다.
- 녹음이 시작되면 아래에서 `spring.dock`으로 솟아오른다. 빨간 점은 1.6초 주기로 숨 쉰다.
- 미니 파형은 마이크·시스템 두 트랙을 합친 12막대다. `recording://level`의 대역 값으로 각 막대의 `scaleY`를 바꾼다(40ms마다, `transform`만).
- 독을 누르면 녹음 화면이 열린다. 독의 파형과 녹음 화면의 큰 파형은 같은 `layoutId`라서 독이 화면 가운데로 펼쳐지듯 이어진다.
- 종료를 누르면 독이 짧아지며 "전사를 시작합니다"로 바뀌고(형태 변화), 1.2초 뒤 아래로 사라진다.
- 녹음 화면에서는 독을 숨긴다(같은 정보가 화면에 크게 있다).

### 6.3 녹음 화면
- 가운데 큰 타이머(`display-xl`)와 그 아래 넓은 파형 두 줄(마이크 `mic`, 시스템 `system`, 막대 24개씩 위아래 대칭). 파형 아래 경고 배너와 전송 고지(RouteNotice).
- 종료 버튼은 `dock` 바탕 알약, 왼쪽에 빨간 사각 아이콘. 단축키 `⌘.`(Windows `Ctrl+.`)를 버튼에 표시한다.

### 6.4 홈: 날짜별 타임라인
```
회의                                         [● 녹음 시작]

오늘 · 10월 15일 수요일
 14:00   주간 개발 회의          ▁▃▅ 요약 중 · 62%
 10:30   디자인 리뷰             ✓ #회의록으로 보냄
어제 · 10월 14일 화요일
 16:00   고객 미팅               ● 검토 대기          ›
```
- 날짜 그룹 제목은 스크롤할 때 위에 붙는다(`sticky`). 그룹 안 행은 처음 열릴 때 35ms 간격으로 떠오른다.
- 행: 왼쪽 시각(`caption`, 고정폭 숫자), 가운데 제목(`body` 600), 오른쪽 상태. 테두리 없이 hover 때 `sunken` 바탕이 행 모양 그대로 깔리고, 오른쪽에 `›`가 미끄러져 나온다.
- 상태 표시는 움직임으로 구분한다.
  - 전사 중: 세 막대가 오르내리는 작은 파형 + "전사 중 · 42%" + 행 아래 1px 진행선
  - 요약 중: "요약 중" 글자에 빛이 왼쪽에서 오른쪽으로 지나가는 반짝임 + 진행선
  - 대기: 점 세 개가 차례로 흐려지는 표시 + "대기 중 · 2번째"
  - 검토 대기: `accent` 점(움직이지 않음)
  - 보냄: `ok-line` 체크 + "#채널로 보냄"
  - 실패: `danger-line` 느낌표 + 오류 한 줄
- 빈 홈: 가운데 `display-m` "첫 회의를 녹음해 보세요"와 큰 녹음 버튼. 버튼 둘레에 옅은 원이 천천히 퍼진다(움직임 줄이기 설정이면 멈춘다).
- 설정 카드(모델·LLM·Slack 없음)는 타임라인 위에 한 줄짜리 알림 띠로 바뀐다. 항목마다 오른쪽에 작은 버튼을 둔다.
- "녹음 시작"은 화면 제목 오른쪽의 `ink` 알약 버튼(흰 글자, 빨간 점)이다. 단축키 `⌘R`.

### 6.5 처리 화면: 파이프라인
```
주간 개발 회의
  녹음 ──── 전사 ──── 요약 ──── 검토
   ✓        ◐ 42%      ○         ○
           구간 2/5 · 약 3분 남음
```
- 네 단계를 가로 트랙으로 보인다. 끝난 단계는 체크, 지금 단계는 원형 진행 표시가 차오르고, 단계 사이 선이 진행률만큼 채워진다.
- 전사본이 생기면 줄이 위에서부터 35ms 간격으로 떠오른다(처음 한 번만).
- 요약 중에는 요약 자리에 다섯 섹션 모양의 뼈대(제목 한 줄 + 섹션마다 2~3줄)가 반짝인다. `review`가 되면 뼈대가 실제 문서로 교차 전환되며 검토 화면으로 넘어간다.
- 실패, 다시 실행, 연결 선택, 전송 고지는 지금 기능 그대로 이 구조 안에 둔다.

### 6.6 검토 화면: 문서
- 카드와 입력란 테두리를 없앤다. 문서 폭 680px 가운데 정렬.
- 제목: `display-l` 크기의 입력란. 바탕·테두리 없음, 포커스 때만 아래 2px `accent` 선이 왼쪽에서 펼쳐진다.
- 메타 줄: `14:00 · 42분 · 녹음 홍길동 · 회사 클라우드로 요약` 칩들(`caption`, `sunken` 알약).
- 본문: 자동 높이 textarea(`body-doc`). **"미정" 형광펜**: textarea 뒤에 같은 글자를 같은 글꼴·크기·줄 높이·여백으로 그린 거울 층을 두고, "미정" 글자에만 `marker` 바탕을 깐다. 거울 층은 React 글자 노드만 쓰고(HTML 문자열 금지, 10.4) `aria-hidden`이다. 글자 굵기는 바꾸지 않는다(폭이 달라지면 겹침이 어긋난다). 미정 목록 상자는 문서 아래 "확인할 항목 N개" 접이식으로 남긴다(화면 읽기 프로그램용).
- 전사본: 오른쪽에서 밀려 나오는 패널(420px, `surface`, `float` 그림자). 헤더 오른쪽 "전사본" 버튼으로 연다. Esc로 닫는다. 시각은 고정폭 숫자.
- **보내기 막대**: 문서 아래 떠 있는 `surface` 알약(독과 같은 자리, 녹음 중이면 독 위로 비켜 선다). 왼쪽 채널 선택, 가운데 글자 수 원형 게이지(12,000자까지 차오르고 90%를 넘으면 `warn-line`, 넘으면 `danger-line` + 글자), 오른쪽 "#회의록으로 보내기" 주요 버튼.
- 보내면: 버튼 안의 종이비행기 아이콘이 오른쪽 위로 날아가고(420ms), 버튼이 체크와 "#회의록으로 보냄"으로 바뀐다. 문서는 읽기 전용이 되고 메타 줄에 "보냄 · 14:52 · 수정 3곳"이 붙는다.
- 자동 저장 표시: 제목 옆 작은 점(저장 중 깜박임 → 저장됨 체크가 나타났다 사라짐).

### 6.7 설정
- 왼쪽 탭 목록의 선택 표시가 탭 사이를 `spring.snappy`로 미끄러진다(`layoutId`).
- 스위치 손잡이는 `spring.snappy`. 저장 버튼은 바뀐 내용이 있을 때만 아래 보내기 막대 자리에 떠오른다("저장 안 한 변경 3개 · 저장").

**개발용 미리보기** (`preview.html`, 배포에 들어가지 않음): `@tauri-apps/api/mocks`로 IPC를 가짜로 바꾸고, 여러 상태의 회의(녹음 중, 전사 중, 요약 중, 대기, 검토, 보냄, 실패, 음성 없음)와 녹음 레벨·진행률 이벤트를 흉내 낸다. 녹음하지 않고도 브라우저(`bun run dev` → `/preview.html`)에서 모든 화면과 움직임을 볼 수 있다.
- 왼쪽 아래 패널에서 시나리오(빈 홈 / 여러 상태 / 녹음 중 / 설정 없음)를 고르면 고정 데이터를 처음 상태로 되돌리고 앱을 다시 띄운다. "GPU 경고", "종료 확인"은 Rust가 스스로 보내는 이벤트를 흉내 내 배너와 대화상자를 띄운다.
- 명령은 고정 데이터를 그럴듯하게 바꾼다: 진행률이 오르고 끝나면 다음 회의가 대기열에서 시작하며, 보내기는 1초 뒤 `sent`가 되고, 녹음을 시작하면 40ms마다 레벨이 온다. 명령마다 처리기를 `ipc.ts`에서 그 명령을 보내는 함수의 반환 타입에 묶어 두어, 응답 모양이 어긋나면 `tsc`가 잡는다. 인자는 묶지 않았다(이름이 `ipc.ts` 안에서 바뀌므로).
- 단순화: "여러 상태"는 실행 중 상태를 한 화면에 모두 보이려고 셋을 동시에 돌린다(실제 대기열은 둘, 아키텍처 8.4).

**0단계에서 정한 것**
- 토큰 이름: 이 문서의 `accent`는 Tailwind에서 `primary`(shadcn 컴포넌트)와 `brand`(우리 코드)다. Tailwind의 `accent`는 shadcn 뜻 그대로 hover 바탕(= `sunken`)으로 남긴다. `accent-press`, `accent-tint`와 나머지 색은 이 문서 이름 그대로다.
- 글자는 `font-display text-display-m`처럼 크기 토큰(줄 높이·자간·굵기 포함)과 글꼴을 따로 쓴다. 모서리는 `rounded-control`(10px)·`rounded-float`(16px)·`rounded-full`, 본문 폭은 `max-w-doc`·`max-w-home`·`max-w-wide`다(녹음·처리 중 화면은 760px).
- 세리프 두 폰트에 `tnum`이 없어 타이머는 Pretendard 고정폭 숫자로 쓴다. 이탤릭 숫자는 바뀌지 않는 숫자에만 쓴다(2).
- 버튼 눌림은 CSS(`motion-safe:active:scale-[0.97]`, 120ms, `transform`만)로, 스위치 손잡이는 CSS 전환으로 했다. `spring.snappy`로 바꾸는 것은 3단계다.
- 화면 전환은 `AnimatePresence`의 `popLayout`이다: 나가는 화면은 흐름에서 빠져 겹쳐 사라지고(들어오는 시간의 65%), 들어오는 화면은 바로 자리를 잡아 레이아웃이 흔들리지 않는다.

단계마다 기존 Vitest 테스트를 바뀐 구조에 맞게 고치고, 동작 테스트(자동 저장, 전송, 고지, D6·D8)는 그대로 통과해야 한다.
