# 디자인 시스템: Paper & Pulse

- 상태: 확정 (2026-10-15, 같은 날 2판). 리디자인 구현의 기준이다. 시그니처 연출 네 가지(독↔녹음 화면, 제목 공유 전환, 문서 안의 "작성 중"과 뼈대, 미정 형광펜·보내기)와 녹음 단축키, 개발용 미리보기를 모두 넣는다.
- 2판(2026-10-15): 사용자가 "UI/UX를 완전히 새로 구성해도 된다", "세리프를 Granola처럼 섞어 달라", "앱 안 첫 화면", "부드러운 화면 전환"을 요청했다. 웹 조사([근거와 출처](research/ui-references-2026-10.md))로 구조를 정했다: 날짜 타임라인 + 떠 있는 먹색 독(조사의 B안), 처리 화면을 없애고 회의 문서 하나에서 "작성 중 → 검토 → 보냄"을 보인다.
- 관련: [아키텍처 10.3](architecture.md#103-색상-토큰)의 색상 토큰과 대비 규칙은 이 문서로 옮겨 온다. 접근성 규칙(NFR-09, 10.4)은 그대로 지킨다.

## 1. 방향

사용자 결정(2026-10-15): Granola의 UI/UX를 참고하되 색은 따르지 않는다. "AI가 만든 티"를 없애고, 폰트와 애니메이션을 적극적으로 써서 스타트업 제품처럼 보이게 한다. 같은 날 갱신: 제목은 Granola처럼 세리프로 한다(처음 고른 Wanted Sans는 뺐다).

| 결정 | 내용 |
|---|---|
| 폰트 | 제목·큰 숫자는 세리프(라틴·숫자 Instrument Serif, 한글 Noto Serif KR), 본문·UI Pretendard |
| 색 | 회사 `mainBlue`는 포인트에만 쓴다. 바탕은 따뜻한 종이색 중성색을 새로 둔다 |
| 구조 | 사이드바 없음. 홈은 "지금 할 일" 묶음 + 날짜별 타임라인, 회의 하나는 문서 하나(작성 중·검토·보냄을 같은 자리에서), 살아 있는 상태는 화면 아래 먹색 독 하나가 맡는다 |

이름의 뜻: 바탕은 종이처럼 조용하고(Paper), 소리와 처리 상태가 있는 곳만 살아 움직인다(Pulse). 움직임은 "지금 무언가 일어나고 있다"를 알릴 때만 쓴다. 장식용 움직임은 두지 않는다.

**하지 않는 것**
- 보라·청록 그라데이션, 유리 효과(glassmorphism), 모든 것을 카드에 넣는 레이아웃. AI가 만든 UI의 전형이다.
- 카드마다 테두리와 그림자. 경계는 여백과 가는 구분선으로 만든다. 그림자는 떠 있는 층(독, 팝오버, 대화상자)에만 쓴다.
- 이모지 아이콘. 아이콘은 지금처럼 `lucide-react`만 쓴다(획 두께 1.75로 통일).

## 2. 타이포그래피

폰트 파일은 앱에 넣는다(CSP가 외부 폰트를 막는다). 세 폰트 모두 SIL OFL 1.1이라 `THIRD_PARTY_NOTICES.md`(M6)에 넣는다.

| 역할 | 폰트 | 패키지 (정확한 버전 고정) |
|---|---|---|
| Display 라틴·숫자: 화면 제목, 회의 제목, 큰 숫자 | Instrument Serif (400과 이탤릭만) | `@fontsource/instrument-serif@5.3.0` (기본 CSS + `400-italic.css`) |
| Display 한글 | Noto Serif KR Variable (굵기 200~900) | `@fontsource-variable/noto-serif-kr@5.3.0` (기본 CSS) |
| Text: 본문, UI, 레이블, 타이머 | Pretendard Variable | `pretendard@1.3.9` (`dist/web/variable/pretendardvariable-dynamic-subset.css`) |

- 세 CSS 모두 `unicode-range`로 나뉜 woff2를 쓴다. Vite가 파일을 번들에 넣고, 화면에 쓰인 글자 범위만 읽는다.
- Display는 `"Instrument Serif", "Noto Serif KR Variable", serif`다. Instrument Serif에는 한글이 없어 한글은 Noto Serif KR로 넘어간다. 크기 토큰의 굵기는 한글(Noto Serif KR) 기준이고, Instrument Serif는 한 굵기뿐이라 가짜 굵게를 만들지 않는다(`font-synthesis: style`).
- 숫자: 시간·진행률·글자 수는 `tabular-nums`로 폭을 고정한다. 바뀔 때 글자가 흔들리지 않게 하려는 것이다. Instrument Serif와 Noto Serif KR에는 고정폭 숫자(`tnum`)가 없다(번들 파일을 fontTools로 확인). 그래서 타이머처럼 바뀌는 숫자는 Pretendard 고정폭 숫자로 쓴다.
- **이탤릭 숫자**: Instrument Serif 이탤릭 숫자는 시그니처 포인트다. 큰 개수와 타임라인의 시각처럼 바뀌지 않는 숫자에 `font-display italic`으로 쓴다. 숫자만 감싼다(Noto Serif KR에는 이탤릭이 없어 한글은 기울기만 흉내 낸다).
- 대체 폰트: `"Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`.

**크기 단계** (px / 줄 높이 / 굵기 / 자간)

| 토큰 | 크기 | 줄 높이 | 굵기 | 자간 | 쓰는 곳 |
|---|---|---|---|---|---|
| `display-xl` | 80 | 1.0 | 300 | -0.02em | 녹음 화면 타이머(Pretendard 고정폭 숫자, 가볍게), 큰 이탤릭 숫자 |
| `display-l` | 44 | 1.2 | 450 | -0.015em | 회의 문서 제목, 첫 화면 헤드라인 (세리프) |
| `display-m` | 32 | 1.25 | 450 | -0.015em | 화면 제목, 날짜 머리 (세리프) |
| `title` | 20 | 1.35 | 500 | -0.01em | 날짜 그룹, 섹션 제목, 워드마크 (세리프) |
| `body-doc` | 16 | 1.75 | 400 | 0 | 요약 본문, 전사본 |
| `body` | 15 | 1.55 | 400 | -0.005em | UI 기본 |
| `label` | 13 | 1.4 | 550 | 0 | 레이블, 칩, 버튼 보조 |
| `caption` | 12 | 1.4 | 500 | 0.01em | 시각, 메타 정보 |

- 세리프는 같은 크기에서 산세리프보다 작아 보여 Display 단계를 한 칸씩 키웠다(72/40/28/18 → 80/44/32/20).
- 한글 세리프 굵기는 450~500이다. Instrument Serif가 400 하나뿐이라 한글을 600으로 두면 "Q3 로드맵 리뷰"처럼 섞인 제목에서 한글만 무거워진다. Granola의 세리프 제목도 400 하나다([근거](research/ui-references-2026-10.md#d-korean-typography-rules)). 한글 제목 자간은 -0.02em보다 좁히지 않는다(두 줄로 넘어갈 때 답답해진다).
- 줄바꿈: `<html lang="ko">`, 제목과 UI 글자는 `word-break: keep-all` + `overflow-wrap: break-word`(넘칠 때만 끊는다. `anywhere`는 flex 안 버튼의 최소 폭을 한 글자로 줄여 좁은 창에서 버튼 글자가 한 자씩 접힌다). 제목에 `text-wrap: balance`는 지원하는 WebKit에서만 걸리는 덤이다.
- 본문 글자는 13px 미만으로 쓰지 않는다. `caption`은 시각·메타처럼 짧은 정보에만 쓴다.

## 5. 모션

라이브러리: `motion@13.4.6` (`motion/react`, MIT). 공개된 지 2주가 넘은 버전으로 고정한다.

**토큰** (`src/lib/motion.ts` 한 곳에 둔다)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `spring.snappy` | stiffness 520, damping 38 | 버튼 눌림, 스위치, 탭 표시자 |
| `spring.gentle` | stiffness 260, damping 30 | 레이아웃 이동, 공유 요소(제목이 목록에서 문서로) |
| `spring.dock` | stiffness 380, damping 28, mass 0.9 | 녹음 독 등장·형태 변화 |
| `dur.micro` / `small` / `medium` / `large` | 120 / 200 / 320 / 480ms | 색·불투명도 전환 |
| `ease.out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 들어올 때 |
| `ease.in` | `cubic-bezier(0.55, 0, 1, 0.45)` | 나갈 때. 나가는 시간은 들어오는 시간의 65% |
| `stagger` | 35ms | 목록 행 등장 |

**규칙**
- `transform`과 `opacity`만 움직인다. 너비·높이·위치 속성은 움직이지 않는다(레이아웃 흔들림 방지). 높이가 바뀌는 곳은 `layout` 애니메이션을 쓴다.
- 화면 하나에서 동시에 눈에 띄게 움직이는 요소는 1~2개다.
- 움직임은 사용자 입력을 막지 않는다. 진행 중인 애니메이션은 새 입력이 오면 그 자리에서 바뀐다.
- **움직임 줄이기**: 앱 최상단에 `<MotionConfig reducedMotion="user">`를 둔다. OS 설정이 켜져 있으면 이동·크기 변화는 끄고 불투명도 전환만 남긴다. CSS 애니메이션(파형, 반짝임)은 `motion-safe:`로만 건다.
- 테스트: `src/test-setup.ts`에서 `MotionGlobalConfig.skipAnimations = true`로 애니메이션을 건너뛴다.
- 매일 보는 화면(홈, 문서)의 UI 움직임은 300ms 이하, 키보드로 한 동작은 움직이지 않는다. 한 번 보는 화면(첫 화면)만 연출을 하나 더 쓴다.
- 25Hz로 바뀌는 값(녹음 레벨)은 React 상태를 거치지 않고 이벤트에서 요소의 `style.transform`(또는 MotionValue)에 바로 쓴다. CSS transition을 걸지 않는다. 둥근 막대는 `scaleY`로 늘이면 끝이 일그러지므로 막대는 끝이 각진 사각형이거나, 위·아래 둥근 마개 두 개를 `translateY`로 벌리는 방식으로 그린다([Granola: don't animate height](https://www.granola.ai/blog/dont-animate-height)).
- 목록 등장 간격은 `transition: { delayChildren: stagger(0.035) }`로 쓴다(`staggerChildren`은 13.4에서 지원 중단).
- 모양이 바뀌는 떠 있는 요소(독)의 모서리 반경은 class가 아니라 `style={{ borderRadius }}`로 준다. 그래야 `layout` 애니메이션 중에 모서리가 일그러지지 않는다. 고정 위치 컨테이너에는 `layoutRoot`를 둔다.
- `AnimatePresence mode="popLayout"`의 직속 자식은 DOM 요소에 `ref`가 닿아야 한다. `mode="wait"`는 화면 전환에 쓰지 않는다(시간이 두 배가 된다).
- popLayout은 실행 중에 `<style>`을 넣는다. 빌드한 앱(`tauri build`)의 CSP에서 화면 전환이 동작하는지 확인한다. 막히면 `MotionConfig`의 `nonce`로 넘긴다.

## 6. 화면별 설계 (2판)

화면은 넷이다: **첫 화면**(회의가 하나도 없을 때의 홈), **홈**, **녹음**, **회의 문서**. 처리 중 화면과 검토 화면은 회의 문서 하나로 합친다. 설정은 그대로 따로 둔다. 근거는 [조사 보고](research/ui-references-2026-10.md) E.

### 6.1 앱 셸
- **헤더** (48px, 바탕은 `paper` 92% + 뒤 흐림, 아래 `line`): 왼쪽 워드마크 "회의 요약"(세리프 `title`, 앞에 작은 파형 로고 3막대: 처리 중일 때만 움직인다), 오른쪽 설정 버튼. 상태 칩은 없앤다. 녹음과 처리는 독이 보인다.
- **화면 전환**: 홈 → 회의 문서·녹음은 "앞으로"(새 화면이 아래 8px에서 떠오름, 320ms, `ease.out`), 그 반대는 "뒤로"(위에서 내려옴). 뒤로 가기는 언제나 홈으로 간다(다른 회의로 가지 않는다). 나가는 화면은 들어오는 시간의 65%로 사라지고 `inert`다.
- **제목 공유 전환**: 홈 행의 제목과 문서 제목은 같은 `layoutId`다. `layoutId`는 입력란이 아니라 그것을 감싼 `motion.div`에 두고 `layout="position"`을 쓴다(글자가 늘어나지 않고 자리만 미끄러진다). 홈 행의 제목도 세리프라 글꼴은 바뀌지 않고 크기만 바뀐다. 홈이 요소 안에서 스크롤되면 그 요소에 `layoutScroll`을 둔다.
- **배너와 짧은 확인**: 배너는 위치 `layout`으로 밀려 들어오고 나간다. "복사했습니다", "저장됨" 같은 확인은 그 자리의 작은 글자로 나타났다 사라진다(3초). 모달 "처리 중" 화면은 두지 않는다.

### 6.2 독 (화면 아래 가운데, 앱에서 유일하게 살아 있는 요소)
먹색(`dock`) 알약, 높이 56px, `float` 그림자, `style={{ borderRadius: 28 }}`, 고정 위치 `layoutRoot`. 상태에 따라 모양이 바뀐다(`layout` + 안쪽 `AnimatePresence mode="popLayout"`, 글자는 `layout="position"`, `spring.dock`).

| 상태 | 내용 | 누르면 |
|---|---|---|
| 녹음 중 | 숨 쉬는 빨간 점, 미니 파형 12막대, 경과 시간(Pretendard 고정폭), "■ 종료 ⌘." | 녹음 화면 |
| 처리 중 (녹음 아님) | 작은 원형 진행 표시 + "처리 중 2" + 지금 일 한 줄("디자인 리뷰 요약 2/3") | 처리 중인 첫 회의 문서 |
| 없음 | 독이 아래로 사라진다 | |

- 녹음 시작: 아래에서 솟아오른다. 종료: 짧아지며 "전사를 시작합니다"로 바뀐 뒤 처리 중 모양으로 넘어간다.
- 녹음 화면에서는 독을 숨긴다. 독 바탕과 녹음 화면 파형 바탕은 같은 `layoutId`라 독이 화면 가운데로 펼쳐지듯 이어진다(막대 수가 달라 막대끼리는 잇지 않고 교차 전환).
- 앱이 포커스를 잃으면 트레이가 상태를 보인다(M5). Granola식 화면 가장자리 떠 있는 표시는 두지 않는다(항상 위 창이 하나 더 필요하다).
- 회의 문서가 보내기 단계에 있으면 보내기 막대가 같은 자리에 같은 모양 언어(흰 `surface` 알약)로 뜬다. 녹음 중이면 보내기 막대는 독 위로 비켜 선다.

### 6.3 녹음 화면
- 가운데 위: "녹음 중 · 14:00 시작"(숨 쉬는 점). 큰 타이머(`display-xl`, Pretendard 고정폭, 자리마다 숫자가 굴러 바뀐다: 200ms `ease.out`).
- 넓은 파형: 마이크(`mic`)와 시스템 오디오(`system`)를 막대 하나에 합치지 않고 위아래 대칭 두 줄로, 막대 24개씩. 레벨은 DOM에 바로 쓴다(5장).
- 아래: 전송 고지와 "로컬로 요약" 스위치, 헤드폰 안내, 경고 배너, 종료 버튼(`ink` 알약, 빨간 사각, `⌘.`). 위 왼쪽 "← 홈"은 녹음을 멈추지 않는다("녹음은 계속돼요").

### 6.4 홈
```
10월 15일 수요일                                  [● 녹음 시작 ⌘R]

지금 할 일
 14:00  디자인 리뷰            요약 중 · 2/3      (반짝임)
 10:00  주간 제품 회의          미정 2 · 검토하기 →
오늘
 15:10  엔지니어링 싱크         전사 중 42% · 약 3분
 09:00  채용 인터뷰 디브리프     #채용으로 보냄 ✓
어제 · 10월 14일 화요일
 …
```
- 머리: 오늘 날짜를 세리프 `display-m`으로("10월 15일" + 작은 "수요일"), 오른쪽 `ink` 알약 "녹음 시작 ⌘R".
- **지금 할 일**: 처리 중이거나 검토를 기다리는 회의를 맨 위에 모은다(Granola의 "Coming up"을 우리 일에 맞게 바꾼 것). 그 아래 날짜 묶음(오늘, 어제, 그 전은 날짜). 같은 회의가 두 번 나오지 않는다.
- 행은 카드가 아니다: 왼쪽 시각(세리프 이탤릭 숫자, 바뀌지 않는 숫자), 가운데 제목(세리프 `title` 크기 18, 굵기 500), 오른쪽 상태와 **행마다 상태에 맞는 동작 하나**(검토하기, 다시 시도, 처리 계속). 구분선은 가늘게, hover 때 `sunken` 바탕.
- 상태 표시: 전사 중 = 세 막대 + %·남은 시간 + 행 아래 1px 진행선, 요약 중 = 글자 아래로 지나가는 반짝임, 대기 = 점 세 개 + "대기 중 · 2번째", 검토 대기 = 브랜드 점, 보냄 = `ok-line` 체크 + "#채널로 보냄", 실패 = `danger-line` 느낌표 + 오류 한 줄.
- 처음 열릴 때 행이 35ms 간격으로 떠오른다(한 번만, 다시 그릴 때는 움직이지 않는다).
- 설정이 빠졌으면 머리 아래 한 줄: "요약까지 하려면 · 전사 모델 받는 중 42% · LLM 연결 · Slack 채널" (각각 링크, 모델은 그 자리에서 받는다).

### 6.5 첫 화면 (회의가 하나도 없을 때의 홈)
- 한 번 보는 화면이라 연출을 하나 쓴다. 세리프 `display-l` 헤드라인 두 줄("회의가 끝나면, / 기록은 이미 와 있어요."), 한 줄 설명, 큰 원형 녹음 버튼(먹색 원 + 빨간 점, 둘레에 원이 천천히 퍼진다), "첫 회의 녹음하기 ⌘R".
- 그 아래 네 단계를 한 줄로(1 녹음 — 2 이 PC에서 전사 — 3 요약 검토 — 4 Slack으로 보내기, 이탤릭 숫자).
- 맨 아래 6.4의 설정 한 줄. 투어·체크리스트·설정 강요는 없다. 녹음은 설정 없이 된다.
- 첫 회의를 녹음하면 이 화면은 다시 나오지 않는다(회의가 생기므로).

### 6.6 회의 문서 (처리 중 + 검토 + 보냄)
문서 폭 680px. 같은 머리를 상태와 상관없이 같은 자리에 둔다: 메타 줄(`caption`: "10월 15일 수 10:00 · 42분 · 녹음 홍길동 · 회사 클라우드로 보내 요약함"), 세리프 `display-l` 제목.

| 상태 | 본문 자리 |
|---|---|
| 대기·전사 중 | 단계 줄(녹음 ✓ — 전사 42% — 요약 — 검토, 지금 단계에 숫자가 오른다, 숫자는 MotionValue로 리렌더 없이) + 전송 고지·"로컬로 요약" + 아래에 다섯 섹션 모양 뼈대(옅게) |
| 요약 중 ("작성 중") | 뼈대가 반짝인다. "요약을 쓰고 있어요 · 2/3" |
| 검토 | 뼈대가 섹션 단위로 실제 글로 바뀐다(섹션마다 40ms 간격 불투명도 + 4px, 처음 한 번). 끝나면 편집기로 바뀐다 |
| 보냄 | 읽기 전용, 메타 줄에 "#회의록으로 보냄 · 14:52 · 수정 3곳" |
| 실패 | 오류와 다시 실행(연결 고르기), 전사본은 그대로 볼 수 있다 |

- 제목은 테두리 없는 입력란이다. 포커스 때만 아래 2px 브랜드 선이 왼쪽에서 펼쳐진다. 제목이 아직 없으면 "제목은 요약 뒤에 붙어요"(흐린 글자).
- 본문: 자동 높이 textarea(`body-doc`). **"미정" 형광펜**은 textarea 뒤 거울 층(같은 글꼴·크기·줄 높이·여백, React 글자 노드만, `aria-hidden`)에 `marker` 바탕을 깐다. 굵기는 바꾸지 않는다. 미정 목록은 문서 아래 "확인할 항목 N개"로 남긴다(화면 읽기 프로그램용).
- **전사본**: 오른쪽 패널(400px, `surface`, `float` 그림자), 위 오른쪽 "전사본" 버튼과 Esc. 시각(Pretendard 고정폭) + 글. 우리 전사본은 두 트랙을 합친 것이라 나/상대 말풍선은 만들지 않는다.
- **보내기 막대**: 요약이 생긴 뒤에만 뜬다(Granola가 공유 버튼을 요약 전까지 숨기는 것과 같다). 독 자리의 흰 알약: 채널 선택, 글자 수 원형 게이지(90% 넘으면 `warn-line`, 넘으면 `danger-line` + 글자), "#회의록으로 보내기". 보내면 종이비행기가 오른쪽 위로 날아가고(300ms) 체크와 "#회의록으로 보냄"으로 바뀐다.
- 자동 저장 표시: 메타 줄 끝의 작은 글자("저장 중…" → "저장됨").
- 더보기(⋯): 요약 복사, `.md`로 저장, 전송 안 함, 삭제.

### 6.7 설정
- 왼쪽 탭 목록, 선택 표시가 탭 사이를 `spring.snappy`로 미끄러진다(`layoutId`). 스위치 손잡이는 `spring.snappy`.
- 저장 버튼은 바뀐 내용이 있을 때만 독 자리에 흰 알약으로 떠오른다("저장 안 한 변경 3개 · 저장").

| 3. 설정·마감 | 설정 탭, 저장 막대, 마이크로 인터랙션, 움직임 줄이기·키보드·대비 점검 |

**개발용 미리보기** (`preview.html`, 배포에 들어가지 않음): `@tauri-apps/api/mocks`로 IPC를 가짜로 바꾸고, 여러 상태의 회의(녹음 중, 전사 중, 요약 중, 대기, 검토, 보냄, 실패, 음성 없음)와 녹음 레벨·진행률 이벤트를 흉내 낸다. 녹음하지 않고도 브라우저(`bun run dev` → `/preview.html`)에서 모든 화면과 움직임을 볼 수 있다.
- 왼쪽 아래 패널에서 시나리오(빈 홈 / 여러 상태 / 녹음 중 / 설정 없음)를 고르면 고정 데이터를 처음 상태로 되돌리고 앱을 다시 띄운다. "GPU 경고", "종료 확인"은 Rust가 스스로 보내는 이벤트를 흉내 내 배너와 대화상자를 띄운다.
- 명령은 고정 데이터를 그럴듯하게 바꾼다: 진행률이 오르고 끝나면 다음 회의가 대기열에서 시작하며, 보내기는 1초 뒤 `sent`가 되고, 녹음을 시작하면 40ms마다 레벨이 온다. 명령마다 처리기를 `ipc.ts`에서 그 명령을 보내는 함수의 반환 타입에 묶어 두어, 응답 모양이 어긋나면 `tsc`가 잡는다. 인자는 묶지 않았다(이름이 `ipc.ts` 안에서 바뀌므로).
- 단순화: "여러 상태"는 실행 중 상태를 한 화면에 모두 보이려고 셋을 동시에 돌린다(실제 대기열은 둘, 아키텍처 8.4).
- 시나리오(1단계): "첫 화면"은 회의도 설정도 모델도 없는 실제 첫 실행이라 첫 화면과 설정 줄이 함께 보인다. "여러 상태"는 지금 할 일(처리 중·대기·검토·실패·중단)과 오늘·어제·그 전 날짜 묶음, 처리 중 독을 보인다. "녹음 중"은 녹음 독, "설정 없음"은 회의 둘과 설정 줄이 있는 홈이다.

**0단계에서 정한 것**
- 토큰 이름: 이 문서의 `accent`는 Tailwind에서 `primary`(shadcn 컴포넌트)와 `brand`(우리 코드)다. Tailwind의 `accent`는 shadcn 뜻 그대로 hover 바탕(= `sunken`)으로 남긴다. `accent-press`, `accent-tint`와 나머지 색은 이 문서 이름 그대로다.
- 글자는 `font-display text-display-m`처럼 크기 토큰(줄 높이·자간·굵기 포함)과 글꼴을 따로 쓴다. 모서리는 `rounded-control`(10px)·`rounded-float`(16px)·`rounded-full`, 본문 폭은 `max-w-doc`·`max-w-home`·`max-w-wide`다(녹음·처리 중 화면은 760px).
- 세리프 두 폰트에 `tnum`이 없어 타이머는 Pretendard 고정폭 숫자로 쓴다. 이탤릭 숫자는 바뀌지 않는 숫자에만 쓴다(2).
- 버튼 눌림은 CSS(`motion-safe:active:scale-[0.97]`, 120ms, `transform`만)로, 스위치 손잡이는 CSS 전환으로 했다. `spring.snappy`로 바꾸는 것은 3단계다.
- 화면 전환은 `AnimatePresence`의 `popLayout`이다: 나가는 화면은 흐름에서 빠져 겹쳐 사라지고(들어오는 시간의 65%), 들어오는 화면은 바로 자리를 잡아 레이아웃이 흔들리지 않는다.

**1단계에서 정한 것**
- 제목 공유 전환(6.1)은 회의 문서와 함께 2단계에서 한다. 지금 문서 쪽 제목이 처리 중·검토 두 화면에 나뉘어 있어서다. 홈 행의 제목은 자기 요소에 따로 두어 `layoutId` 래퍼를 바로 씌울 수 있다. 독 바탕과 녹음 화면 파형의 `layoutId` 이음(6.2)도 하지 않았다. 독은 녹음 화면에서 숨는다.
- 화면 전환 방향은 `AnimatePresence`의 `custom`으로 넘긴다(`{ dir, instant }`). 홈으로 가면 뒤로, 그 밖은 앞으로다. 단축키가 일으킨 전환은 `instant`라 움직이지 않는다(5의 "키보드로 한 동작"). 녹음 종료는 `stop_recording`의 응답과 `recording://stopped` 중 먼저 온 쪽이 그 표시를 가져간다. 독의 모양 변화는 상태 변화라 단축키로 시작해도 그대로 움직인다.
- 독의 "처리 중 N"은 실행 중 + 대기다(트레이의 "처리 중"과 같은 셈). 지금 일 한 줄은 줄 맨 앞 회의(실행 중 먼저, 그다음 대기 순서)이고, 제목이 아직 없으면 "14:00 회의"로 부른다. 전사 중이면 "전사 42%"(퍼센트는 MotionValue 글자), 요약 요청이 둘 이상이면 "요약 2/3", 셀 것이 없으면 원 대신 4분의 1 호가 돈다(`motion-safe:`). 대기만 있으면 빈 원과 "대기 중"이다.
- 2차(같은 날, 리뷰와 시각 점검 뒤): 첫 등장은 앞의 8행까지만 기다린다(마지막도 280ms 안). 녹음 화면은 한 열로 가운데 모아 창 높이의 가운데에 둔다. 파형은 줄마다 3px 막대 48개(24대역을 가운데에서 바깥으로), 범례는 파형 아래 가운데, 타이머는 "12:43"(한 시간부터 "1:02:03")에 Pretendard 300이다(`display-xl` 굵기 300). 첫 화면도 창 높이의 가운데다. 설정 줄은 짧은 링크("전사 모델 받기", "LLM 연결", "Slack 채널 연결")이고 "전사 설정"은 받는 중·실패일 때만 흐리게 붙는다. 조사는 "(으)로" 대신 `josa`로 고른다. 반짝임은 글자 상자 밖으로 나가지 않는다(`overflow-hidden`). `⌘R`을 설정 화면에서 누르면 저장하지 않은 입력을 지키려고 화면을 옮기지 않고 독만 녹음을 보인다. 단축키는 열린 선택 목록·메뉴에서도 쉰다. 스스로 끝난 녹음은 목록이 따라올 때까지 독이 "전사를 시작합니다"로 잇고, 독의 "종료"를 누르면 포커스가 알약으로 옮겨 모양이 바뀌어도 남는다. 단축키 표시는 불투명도 70%(종이 위 4.5:1 이상)다.
- 독 미니 파형 12막대는 24대역을 넷씩 묶은 6단계를 가운데가 낮은 대역이 되게 좌우로 펼친 것이다(마이크와 시스템 중 큰 값, `rec` 색, 끝이 각진 막대에 `scaleY`). 경과 시간의 첫 값은 회의의 `created_at`에서 채워, 홈으로 돌아올 때마다 숫자가 0부터 굴러오지 않는다.
- 녹음 종료를 누르면 독은 목록이 녹음 끝을 보일 때까지 "전사를 시작합니다"다. 시작·종료는 `App.tsx` 한 곳이 맡고(홈, 첫 화면, 독, 녹음 화면, 단축키가 같이 쓴다) 실패는 앱의 닫을 수 있는 경고 배너로 보인다.
- 상태 변화는 독 아래 숨은 `role="status"` 한 줄이 한 번씩 말한다: "녹음을 시작했습니다", "녹음을 마쳤습니다. 처리를 시작합니다", "처리를 시작했습니다", "처리를 마쳤습니다". 독은 첫 목록을 읽은 뒤에 붙어서, 앱을 연 순간의 상태는 말하지 않는다.
- 지금 할 일: 녹음 중, 처리 중·대기(다시 시도해 줄에 선 실패 포함), 검토 대기(음성 없음 포함), 실패, 중단된 녹음. 새 버전 앱의 회의는 읽기만 하므로 날짜 묶음에 "새 버전 앱의 회의"로 둔다. 지금 할 일 안의 다른 날 회의는 시각 아래 "어제"나 "10월 12일"을 붙인다. 묶음 제목 옆 개수는 이탤릭 숫자다.
- 행 동작: 녹음 중 → "녹음 화면으로", 중단된 녹음 → "처리 계속"(옆에 "삭제", 열 화면이 없어 행 자체는 누르지 않는다), 검토 대기 → "검토하기", 전사 실패 → "다시 시도", 요약 실패 → "요약 다시 실행"(연결을 고르는 처리 화면을 연다, SUM-07). 처리 중·대기·보냄·전송 안 함·전사 완료에는 없다. 보낸 회의는 "#회의록으로 보냄", 제목이 없는 행은 `ink-2`의 "42분 녹음"(녹음 중이면 "녹음 중인 회의")이다. 전사 중 행은 "전사 42% · 약 3분 남음"과 행 아래 1px 진행선이다.
- 첫 화면은 회의가 하나도 없을 때만이다. 목록을 읽기 전에는 홈 본문을 비워 첫 화면이 일반 홈 앞에서 깜빡이지 않게 하고, 읽기에 실패하면 일반 홈(녹음 시작 있음)을 보인다. 연출은 녹음 버튼 둘레에 엇갈려 퍼지는 원 둘(2.8초, `animate-ring`)이다.
- 행이 떠오르는 연출은 앱을 실행한 뒤 첫 홈에서 한 번만 한다(모듈 변수). 홈은 화면이 바뀔 때마다 새로 마운트되기 때문이다. 첫 등장 뒤 다른 묶음으로 옮겨 붙는 행도 움직이지 않는다.
- 단축키: `⌘R` 녹음 시작, `⌘.` 녹음 종료(Windows는 `Ctrl`). 키는 `e.code`로 본다(한글 입력 중에도 `KeyR`). 입력란·대화상자에서는 아무것도 하지 않지만 `preventDefault`는 늘 해 웹뷰가 새로 고쳐지지 않는다. 녹음 중이거나 시작 중이면 `⌘R`은 무시한다. 버튼에는 `aria-keyshortcuts`와 화면용 `⌘R` 표시(`aria-hidden`)를 둔다. macOS 앱 메뉴에는 두 키와 겹치는 항목이 없다. Windows WebView2의 자체 `Ctrl+R`이 페이지의 `preventDefault`보다 먼저 도는지는 확인하지 못했다(Windows 미검증).
