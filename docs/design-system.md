# 디자인 시스템: Paper & Pulse

- 상태: 확정 (2026-10-15, 같은 날 2판). 리디자인 구현의 기준이다. 시그니처 연출 네 가지(독↔녹음 화면, 제목 공유 전환, 문서 안의 "작성 중"과 뼈대, 미정 형광펜·보내기)와 녹음 단축키, 개발용 미리보기를 모두 넣는다.
- 2판(2026-10-15): 사용자가 "UI/UX를 완전히 새로 구성해도 된다", "세리프를 Granola처럼 섞어 달라", "앱 안 첫 화면", "부드러운 화면 전환"을 요청했다. 웹 조사([근거와 출처](research/ui-references-2026-10.md))로 구조를 정했다: 날짜 타임라인 + 떠 있는 먹색 독(조사의 B안), 처리 화면을 없애고 회의 문서 하나에서 "작성 중 → 검토 → 보냄"을 보인다.
- 3판(2026-10-16): 사용자 피드백: 세리프는 포인트에만, 포인트 색을 종이 톤에 맞게, UI에 em dash 금지, 헤더에 회사 로고. 정한 것은 [7장 끝](#7-구현-순서)에 있다.
- 관련: [아키텍처 10.3](architecture.md#103-색상-토큰)의 색상 토큰과 대비 규칙은 이 문서로 옮겨 온다. 접근성 규칙(NFR-09, 10.4)은 그대로 지킨다.

## 1. 방향

사용자 결정(2026-10-15): Granola의 UI/UX를 참고하되 색은 따르지 않는다. "AI가 만든 티"를 없애고, 폰트와 애니메이션을 적극적으로 써서 스타트업 제품처럼 보이게 한다. 같은 날 갱신: 제목은 Granola처럼 세리프로 한다(처음 고른 Wanted Sans는 뺐다). 3판(2026-10-16)에서 세리프는 포인트가 되는 제목 다섯 곳에만 남겼다(2).

| 결정 | 내용 |
|---|---|
| 폰트 | 세리프(라틴·숫자 Instrument Serif, 한글 Noto Serif KR)는 포인트가 되는 화면 제목과 회의 문서 제목에만 쓰고, 나머지 제목·본문·UI는 Pretendard |
| 색 | 포인트 색은 회사 `mainBlue`와 같은 색상각에서 채도를 낮춘 먹빛 인디고(`#4950B0`)이고 포인트에만 쓴다. 바탕은 따뜻한 종이색 중성색을 새로 둔다 |
| 구조 | 사이드바 없음. 홈은 "지금 할 일" 묶음 + 날짜별 타임라인, 회의 하나는 문서 하나(작성 중·검토·보냄을 같은 자리에서), 살아 있는 상태는 화면 아래 먹색 독 하나가 맡는다 |

이름의 뜻: 바탕은 종이처럼 조용하고(Paper), 소리와 처리 상태가 있는 곳만 살아 움직인다(Pulse). 움직임은 "지금 무언가 일어나고 있다"를 알릴 때만 쓴다. 장식용 움직임은 두지 않는다.

**하지 않는 것**
- 보라·청록 그라데이션, 유리 효과(glassmorphism), 모든 것을 카드에 넣는 레이아웃. AI가 만든 UI의 전형이다.
- 카드마다 테두리와 그림자. 경계는 여백과 가는 구분선으로 만든다. 그림자는 떠 있는 층(독, 팝오버, 대화상자)에만 쓴다.
- 이모지 아이콘. 아이콘은 지금처럼 `lucide-react`만 쓴다(획 두께 1.75로 통일).

**앱 아이콘** (2026-10-29): 회사 심볼(보라색 네 조각, `src-tauri/icons/source/sije-symbol.png`)을 흰 둥근 사각형 가운데에 둔다. macOS(`icon.icns`)는 Apple 아이콘 틀대로 1024 캔버스에 여백 100의 824 사각형(모서리 185)과 높이 400의 로고, 그 밖의 크기(Windows `icon.ico`, 트레이가 쓰는 PNG)는 여백 없는 1024 사각형(모서리 225)과 높이 500의 로고다. 두 원본은 `src-tauri/icons/source/`에 있고, `bun tauri icon <원본>`이 만든 파일 중 `icon.icns`는 macOS 원본에서, 나머지는 여백 없는 원본에서 가져온다.

## 2. 타이포그래피

폰트 파일은 앱에 넣는다(CSP가 외부 폰트를 막는다). 세 폰트 모두 SIL OFL 1.1이라 `THIRD_PARTY_NOTICES.md`(M6)에 넣는다.

| 역할 | 폰트 | 패키지 (정확한 버전 고정) |
|---|---|---|
| Display 라틴·숫자: 포인트 제목(아래) | Instrument Serif (400만) | `@fontsource/instrument-serif@5.3.0` (기본 CSS) |
| Display 한글 | Noto Serif KR Variable (굵기 200~900) | `@fontsource-variable/noto-serif-kr@5.3.0` (기본 CSS) |
| Text: 본문, UI, 레이블, 섹션 제목, 타이머 | Pretendard Variable | `pretendard@1.3.9` (`dist/web/variable/pretendardvariable-dynamic-subset.css`) |

- 세 CSS 모두 `unicode-range`로 나뉜 woff2를 쓴다. Vite가 파일을 번들에 넣고, 화면에 쓰인 글자 범위만 읽는다.
- Display는 `"Instrument Serif", "Noto Serif KR Variable", serif`다. Instrument Serif에는 한글이 없어 한글은 Noto Serif KR로 넘어간다. 크기 토큰의 굵기는 한글(Noto Serif KR) 기준이고, Instrument Serif는 한 굵기뿐이라 가짜 굵게를 만들지 않는다. 이탤릭도 쓰지 않아 `font-synthesis: none`이다.
- 숫자: 시간·진행률·글자 수는 `tabular-nums`로 폭을 고정한다. 바뀔 때 글자가 흔들리지 않게 하려는 것이다. Instrument Serif와 Noto Serif KR에는 고정폭 숫자(`tnum`)가 없다(번들 파일을 fontTools로 확인). 그래서 타이머처럼 바뀌는 숫자는 Pretendard 고정폭 숫자로 쓴다.
- **세리프는 포인트에만** (3판): 첫 화면 헤드라인과 회의 문서 제목(`display-l`), 홈 날짜 머리("10월 16일", 요일은 Pretendard), 화면 제목(`Page`의 `h1`, 예: "설정"), 녹음 화면의 "진행 중인 녹음이 없습니다"(`display-m`)만 세리프다. 날짜 그룹·설정 탭·문서 섹션 제목, 전사본 패널과 대화상자 제목, 홈 행의 시각과 제목, 워드마크는 Pretendard다. 이탤릭은 쓰지 않는다.
- 대체 폰트: `"Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`.

**크기 단계** (px / 줄 높이 / 굵기 / 자간)

| 토큰 | 크기 | 줄 높이 | 굵기 | 자간 | 쓰는 곳 |
|---|---|---|---|---|---|
| `display-xl` | 80 | 1.0 | 300 | -0.02em | 녹음 화면 타이머(Pretendard 고정폭 숫자, 가볍게) |
| `display-l` | 44 | 1.2 | 450 | -0.015em | 회의 문서 제목, 첫 화면 헤드라인 (세리프) |
| `display-m` | 32 | 1.25 | 450 | -0.015em | 화면 제목, 날짜 머리 (세리프) |
| `title` | 18 | 1.4 | 600 | -0.01em | 날짜 그룹, 설정 탭·문서 섹션 제목, 대화상자 제목 (Pretendard) |
| `body-doc` | 16 | 1.75 | 400 | 0 | 요약 본문, 전사본 |
| `body` | 15 | 1.55 | 400 | -0.005em | UI 기본 |
| `label` | 13 | 1.4 | 550 | 0 | 레이블, 칩, 버튼 보조 |
| `caption` | 12 | 1.4 | 500 | 0.01em | 시각, 메타 정보 |

- 세리프는 같은 크기에서 산세리프보다 작아 보여 Display 단계를 한 칸씩 키웠다(72/40/28 → 80/44/32). `title`은 3판에서 Pretendard 제목이 되어 18로 돌아왔다.
- 한글 세리프 굵기는 450~500이다. Instrument Serif가 400 하나뿐이라 한글을 600으로 두면 "Q3 로드맵 리뷰"처럼 섞인 제목에서 한글만 무거워진다. Granola의 세리프 제목도 400 하나다([근거](research/ui-references-2026-10.md#d-korean-typography-rules)). 한글 제목 자간은 -0.02em보다 좁히지 않는다(두 줄로 넘어갈 때 답답해진다).
- 줄바꿈: `<html lang="ko">`, 제목과 UI 글자는 `word-break: keep-all` + `overflow-wrap: break-word`(넘칠 때만 끊는다. `anywhere`는 flex 안 버튼의 최소 폭을 한 글자로 줄여 좁은 창에서 버튼 글자가 한 자씩 접힌다). 제목에 `text-wrap: balance`는 지원하는 WebKit에서만 걸리는 덤이다.
- 본문 글자는 13px 미만으로 쓰지 않는다. `caption`은 시각·메타처럼 짧은 정보에만 쓴다.

## 5. 모션

라이브러리: `motion@13.4.6` (`motion/react`, MIT). 공개된 지 2주가 넘은 버전으로 고정한다.

**토큰** (`src/lib/motion.ts` 한 곳에 둔다)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `spring.snappy` | stiffness 520, damping 38 | 버튼 눌림, 스위치, 탭 표시자 |
| `spring.gentle` | stiffness 260, damping 30 | 레이아웃 이동 (제목 공유 전환은 300ms 상한 때문에 `titleMove` tween, 7의 2단계) |
| `spring.dock` | stiffness 380, damping 28, mass 0.9 | 녹음 독 등장·형태 변화 |
| `dur.micro` / `small` / `medium` / `large` | 120 / 200 / 320 / 480ms | 색·불투명도 전환 |
| `ease.out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 들어올 때 |
| `ease.in` | `cubic-bezier(0.55, 0, 1, 0.45)` | 나갈 때. 나가는 시간은 들어오는 시간의 65% |
| `stagger` | 35ms | 목록 행 등장 |

**규칙**
- `transform`과 `opacity`만 움직인다. 너비·높이·위치 속성은 움직이지 않는다(레이아웃 흔들림 방지). 높이가 바뀌는 곳은 `layout` 애니메이션을 쓴다.
- 화면 하나에서 동시에 눈에 띄게 움직이는 요소는 1~2개다.
- 움직임은 사용자 입력을 막지 않는다. 진행 중인 애니메이션은 새 입력이 오면 그 자리에서 바뀐다.
- **움직임 줄이기**: 앱 최상단에 `<MotionConfig reducedMotion="user">`를 둔다. OS 설정이 켜져 있으면 이동·크기 변화는 끄고 불투명도 전환만 남긴다. CSS 애니메이션(파형, 반짝임)은 `motion-safe:`로만 건다.
- 테스트: `src/test-setup.ts`에서 `MotionGlobalConfig.skipAnimations = true`로 애니메이션을 건너뛴다.
- 매일 보는 화면(홈, 문서)의 UI 움직임은 300ms 이하, 키보드로 한 동작은 움직이지 않는다. 한 번 보는 화면(첫 화면)만 연출을 하나 더 쓴다.
- 25Hz로 바뀌는 값(녹음 레벨)은 React 상태를 거치지 않고 이벤트에서 요소의 `style.transform`(또는 MotionValue)에 바로 쓴다. CSS transition을 걸지 않는다. 둥근 막대는 `scaleY`로 늘이면 끝이 일그러지므로 막대는 끝이 각진 사각형이거나, 위·아래 둥근 마개 두 개를 `translateY`로 벌리는 방식으로 그린다([Granola: don't animate height](https://www.granola.ai/blog/dont-animate-height)).
- 목록 등장 간격은 `transition: { delayChildren: stagger(0.035) }`로 쓴다(`staggerChildren`은 13.4에서 지원 중단).
- 모양이 바뀌는 떠 있는 요소(독)의 모서리 반경은 class가 아니라 `style={{ borderRadius }}`로 준다. 그래야 `layout` 애니메이션 중에 모서리가 일그러지지 않는다. 고정 위치 컨테이너에는 `layoutRoot`를 둔다.
- `AnimatePresence mode="popLayout"`의 직속 자식은 DOM 요소에 `ref`가 닿아야 한다. `mode="wait"`는 화면 전환에 쓰지 않는다(시간이 두 배가 된다).
- popLayout은 실행 중에 `<style>`을 넣는다. 빌드한 앱(`tauri build`)의 CSP에서 화면 전환이 동작하는지 확인한다. 막히면 `MotionConfig`의 `nonce`로 넘긴다.

## 6. 화면별 설계 (2판)

화면은 넷이다: **첫 화면**(회의가 하나도 없을 때의 홈), **홈**, **녹음**, **회의 문서**. 처리 중 화면과 검토 화면은 회의 문서 하나로 합친다. 설정은 그대로 따로 둔다. 근거는 [조사 보고](research/ui-references-2026-10.md) E.

### 6.1 앱 셸
- **헤더** (48px, 창 위에 고정되어 스크롤해도 움직이지 않는다, 바탕은 `paper` 92% + 뒤 흐림, 아래 `line`): 왼쪽에 회사 로고(SIJE, `ink`, 높이 14px) + 가는 세로 구분선(`line`) + 워드마크 "회의 요약"(Pretendard `body` 600), 오른쪽 설정 버튼. 파형 막대는 헤더에 두지 않는다. 상태 칩은 없앤다. 녹음과 처리는 독이 보인다.
- **화면 전환**: 홈 → 회의 문서·녹음은 "앞으로"(새 화면이 아래 8px에서 떠오름, 320ms, `ease.out`), 그 반대는 "뒤로"(위에서 내려옴). 뒤로 가기는 언제나 홈으로 간다(다른 회의로 가지 않는다). 나가는 화면은 들어오는 시간의 65%로 사라지고 `inert`다.
- **제목 공유 전환**: 홈 행의 제목과 문서 제목은 같은 `layoutId`다. `layoutId`는 입력란이 아니라 그것을 감싼 `motion.div`에 두고 `layout="position"`을 쓴다(글자가 늘어나지 않고 자리만 미끄러진다). 홈 행의 제목은 Pretendard, 문서 제목은 세리프라 글꼴과 크기는 바로 바뀌고 자리만 미끄러진다. 홈이 요소 안에서 스크롤되면 그 요소에 `layoutScroll`을 둔다.
- **배너와 짧은 확인**: 배너는 위치 `layout`으로 밀려 들어오고 나간다. "복사했습니다", "저장됨" 같은 확인은 그 자리의 작은 글자로 나타났다 사라진다(3초). 모달 "처리 중" 화면은 두지 않는다.

### 6.2 독 (화면 아래 가운데, 앱에서 유일하게 살아 있는 요소)
먹색(`dock`) 알약, 높이 56px, `float` 그림자, `style={{ borderRadius: 28 }}`, 고정 위치 `layoutRoot`. 상태에 따라 모양이 바뀐다(`layout` + 안쪽 `AnimatePresence mode="popLayout"`, 글자는 `layout="position"`, `spring.dock`).

| 상태 | 내용 | 누르면 |
|---|---|---|
| 녹음 중 | 숨 쉬는 빨간 점, 미니 파형 12막대, 경과 시간(Pretendard 고정폭), "■ 종료 ⌘." | 녹음 화면 |
| 녹음 파일 가져오는 중 (REC-12, 녹음 아님) | 처리 중과 같은 모양: 원형 진행 표시 + "녹음 파일 가져오기" + "{파일 이름} · 가져오는 중 42%". 처리 중보다 앞선다(곧 그 줄에 들어간다) | 누를 수 없다 |
| 처리 중 (녹음 아님) | 작은 원형 진행 표시 + "처리 중 2" + 지금 일 한 줄("디자인 리뷰 요약 2/3") | 처리 중인 첫 회의 문서 |
| 없음 | 독이 아래로 사라진다 | |

- 녹음 시작: 아래에서 솟아오른다. 종료: 짧아지며 "전사를 시작합니다"로 바뀐 뒤 처리 중 모양으로 넘어간다.
- 녹음 화면에서는 독을 숨긴다. 독 바탕과 녹음 화면 파형 바탕은 같은 `layoutId`라 독이 화면 가운데로 펼쳐지듯 이어진다(막대 수가 달라 막대끼리는 잇지 않고 교차 전환).
- 앱이 포커스를 잃으면 트레이가 상태를 보인다(M5). Granola식 화면 가장자리 떠 있는 표시는 두지 않는다(항상 위 창이 하나 더 필요하다).
- 회의 문서가 보내기 단계에 있으면 보내기 막대가 같은 자리에 같은 모양 언어(흰 `surface` 알약)로 뜬다. 녹음 중이면 보내기 막대는 독 위로 비켜 선다.
- 1.1.0: 일시정지된 회의의 독 개수와 완료 알림은 [8.3 독](#83-독)을 따른다.

### 6.3 녹음 화면
- 가운데 위: "녹음 중 · 14:00 시작"(숨 쉬는 점). 큰 타이머(`display-xl`, Pretendard 고정폭, 자리마다 숫자가 굴러 바뀐다: 200ms `ease.out`).
- 넓은 파형: 마이크(`mic`)와 시스템 오디오(`system`)를 막대 하나에 합치지 않고 위아래 대칭 두 줄로, 막대 24개씩. 레벨은 DOM에 바로 쓴다(5장).
- 아래: 전송 고지와 "로컬로 요약" 스위치, 헤드폰 안내, 경고 배너, 종료 버튼(`ink` 알약, 빨간 사각, `⌘.`). 위 왼쪽 "← 홈"은 녹음을 멈추지 않는다("녹음은 계속돼요").
- 1.1.0: 녹음 화면의 "전사 언어" 고르기는 [8.7 전사 언어 고르기](#87-전사-언어-고르기-popover와-대화상자)를 따른다.

### 6.4 홈
```
10월 15일 수요일                  [♫ 녹음 파일 가져오기] [● 녹음 시작 ⌘R]

지금 할 일
 14:00  디자인 리뷰            요약 중 · 2/3      (반짝임)
 10:00  주간 제품 회의          미정 2 · 검토하기 →
오늘
 15:10  엔지니어링 싱크         전사 중 42% · 약 3분
 09:00  채용 인터뷰 디브리프     #채용으로 보냄 ✓
어제 · 10월 14일 화요일
 …
```
- 머리: 오늘 날짜를 세리프 `display-m`으로("10월 15일" + 작은 Pretendard "수요일"), 오른쪽 `ink` 알약 "녹음 시작 ⌘R".
- **지금 할 일**: 처리 중이거나 검토를 기다리는 회의를 맨 위에 모은다(Granola의 "Coming up"을 우리 일에 맞게 바꾼 것). 그 아래 날짜 묶음(오늘, 어제, 그 전은 날짜). 같은 회의가 두 번 나오지 않는다.
- 행은 카드가 아니다: 왼쪽 시각(Pretendard `label` 고정폭 숫자), 가운데 제목(Pretendard `body`, 굵기 500), 오른쪽 상태와 **행마다 상태에 맞는 동작 하나**(검토하기, 다시 시도, 처리 계속). 구분선은 가늘게, hover 때 `sunken` 바탕.
- 상태 표시: 전사 중 = 세 막대 + %·남은 시간 + 행 아래 1px 진행선, 요약 중 = 글자 아래로 지나가는 반짝임, 대기 = 점 세 개 + "대기 중 · 2번째", 검토 대기 = 브랜드 점, 보냄 = `ok-line` 체크 + "#채널로 보냄", 실패 = `danger-line` 느낌표 + 오류 한 줄.
- 처음 열릴 때 행이 35ms 간격으로 떠오른다(한 번만, 다시 그릴 때는 움직이지 않는다).
- 설정이 빠졌으면 머리 아래 한 줄: "요약까지 하려면 · 전사 모델 받는 중 42% · LLM 연결 · Slack 채널" (각각 링크, 모델은 그 자리에서 받는다).

- 녹음 파일 가져오기(REC-12, 2026-10-20): 녹음 시작 왼쪽의 ghost 알약(첫 화면은 녹음 버튼 아래). 가져오는 동안 "가져오는 중…"으로 막힌다. 녹음 파일을 창 위로 끌고 오면 화면 전체가 `paper` 90% 위에 `brand` 점선 테두리와 "놓으면 녹음 파일을 가져옵니다", 받는 확장자 한 줄로 바뀐다(나타나고 사라지기만, `dur.small`).
- 1.1.0: 일시정지됨·멈추는 중 행과 "모두 이어서 처리"는 [8.2 홈 "지금 할 일" 행](#82-홈-지금-할-일-행), 보낸 채널 표시는 [8.4 회의 메타 줄](#84-회의-메타-줄), 가져오기 전 언어 고르기는 [8.8 가져오기 언어 대화상자](#88-가져오기-언어-대화상자-관문-d10a)를 따른다.

### 6.5 첫 화면 (회의가 하나도 없을 때의 홈)
- 한 번 보는 화면이라 연출을 하나 쓴다. 세리프 `display-l` 헤드라인 두 줄("간단히 녹음하고, / 요약해 보세요."), 한 줄 설명, 큰 원형 녹음 버튼(먹색 원 + 빨간 점, 둘레에 원이 천천히 퍼진다), "첫 회의 녹음하기 ⌘R".
- 그 아래 네 단계를 한 줄로(1 녹음 › 2 이 PC에서 전사 › 3 요약 검토 › 4 Slack으로 보내기). 숫자는 Pretendard 굵게(`ink`), 사이는 `ChevronRight` 아이콘(`ink-3`)이다.
- 맨 아래 6.4의 설정 한 줄. 투어·체크리스트·설정 강요는 없다. 녹음은 설정 없이 된다.
- 첫 회의를 녹음하면 이 화면은 다시 나오지 않는다(회의가 생기므로).
- 스크롤이 없다(2026-10-20): 헤더 아래 창 높이만큼이고(독 자리는 절반만 남긴다, 독은 아래 80px), 묶음 사이 간격이 창 높이의 5%(16~48px)라 창 크기를 바꿔도 가운데에 들어맞는다. 창의 최소 크기 720×600까지 스크롤이 생기지 않는다.

### 6.6 회의 문서 (처리 중 + 검토 + 보냄)
문서 폭 680px. 같은 머리를 상태와 상관없이 같은 자리에 둔다: 메타 줄(`caption`: "10월 15일 수 10:00 · 42분 · 녹음 홍길동 · 회사 클라우드로 보내 요약함"), 세리프 `display-l` 제목.

| 상태 | 본문 자리 |
|---|---|
| 대기·전사 중 | 단계 줄(녹음 ✓ › 전사 42% › 요약 › 검토, 사이는 `ChevronRight` 아이콘, 지금 단계에 숫자가 오른다, 숫자는 MotionValue로 리렌더 없이) + 전송 고지·"로컬로 요약" + 아래에 다섯 섹션 모양 뼈대(옅게) |
| 요약 중 ("작성 중") | 뼈대가 반짝인다. "요약을 쓰고 있어요 · 2/3" |
| 검토 | 뼈대가 섹션 단위로 읽는 문서로 바뀐다(섹션마다 40ms 간격 불투명도 + 4px, 처음 한 번). 끝나면 같은 문서를 누르거나 "고치기"로 고친다 |
| 보냄 | 읽기 전용, 메타 줄에 "#회의록으로 보냄 · 14:52 · 수정 3곳" |
| 실패 | 오류와 다시 실행(연결 고르기), 전사본은 그대로 볼 수 있다 |

- 제목은 테두리 없는 입력란이다. 포커스 때만 아래 2px 브랜드 선이 왼쪽에서 펼쳐진다. 제목이 아직 없으면 그 자리에 지금 하는 일을 흐린 글자로, 2초마다 다음 문장으로 바꿔 보인다(사용자 요청 2026-10-20): 전사 중 "열심히 듣는 중…"·"말을 글로 옮기는 중…", 요약 중 "열심히 읽는 중…"·"중요한 내용을 고르는 중…", 대기 중 "차례를 기다리는 중…", 그리고 "조금만 기다려 주세요…". 불투명도로만 바뀌어 움직임 줄이기에도 남고, 화면 읽기 프로그램에는 "제목 준비 중" 하나만 들린다. 줄에도 없고 돌지도 않으면(실패, 요약 경로 대기) "제목 없음"이다.
- 본문은 **읽는 문서**다. Markdown 원문("## 결정사항", "- [김지훈] …")을 그대로 보이지 않는다. 우리 줄 파서가 섹션 제목(Pretendard `title`, 위에 여백), 목록(작고 조용한 점, 걸친 들여쓰기), 담당자 칩(`sunken` 알약, `label`, `ink`. 미정이면 `marker`), 끝의 기한(`caption`, `ink-2`. 미정이면 `marker`), "없음"(`ink-2`), 그 밖의 "미정" 형광펜만 알아보고 나머지는 쓴 글자 그대로 둔다. React 글자 노드만 쓴다(NFR-07).
- **누르면 고친다**: 마우스를 올리면 본문에 옅은 `sunken` 바탕, 오른쪽 위에 늘 있는 조용한 "고치기". 줄을 누르면 그 줄 첫 자리에 캐럿을 두고 원문 편집기(자동 높이 textarea, `body-doc`)가 그 자리에 들어서며, 누른 줄은 화면에서 같은 높이에 남는다. Esc나 편집기 밖으로 나간 포커스는 문서로 돌아온다(보내기 막대를 누를 때는 남는다). 둘은 150ms 불투명도로 엇갈려 바뀌고 키보드로 하면 바로 바뀐다. 보냄·전송 안 함은 같은 문서를 읽기 전용으로 보인다.
- 편집기의 **"미정" 형광펜**은 textarea 뒤 거울 층(같은 글꼴·크기·줄 높이·여백, React 글자 노드만, `aria-hidden`)에 `marker` 바탕을 깐다. 굵기는 바꾸지 않는다. 미정 목록은 문서 아래 "확인할 항목 N개"로 남긴다(화면 읽기 프로그램용).
- **전사본**: 오른쪽 패널(400px, `surface`, `float` 그림자), 위 오른쪽 "전사본" 버튼과 Esc. 시각(Pretendard 고정폭) + 글. 우리 전사본은 두 트랙을 합친 것이라 나/상대 말풍선은 만들지 않는다.
- **보내기 막대**: 요약이 생긴 뒤에만 뜬다(Granola가 공유 버튼을 요약 전까지 숨기는 것과 같다). 독 자리의 흰 알약: 채널 선택, 글자 수 원형 게이지(90%부터 `warn-line` + "N자 남음", 넘으면 `danger-line` + "N자를 줄여 주세요"), "#회의록으로 보내기". 보내면 종이비행기가 오른쪽 위로 날아가고(300ms) 체크와 "#회의록으로 보냄"으로 바뀐다.
- 자동 저장 표시: 메타 줄 끝의 작은 글자("저장 중…" → "저장됨").
- 더보기(⋯): 요약 복사, `.md`로 저장, 전송 안 함, 삭제.
- 1.1.0: 처리 영역의 일시정지 버튼과 단계 줄은 [8.1](#81-회의-문서-처리-영역), 메타 줄은 [8.4](#84-회의-메타-줄), 보낸 회의의 보내기 막대는 [8.5](#85-보내기-막대-보낸-회의의-알약), 더보기 메뉴(녹음 파일 저장, 전사 언어 바꾸기)는 [8.6](#86-더보기-메뉴), 전사본 패널의 언어 이름과 날짜 미확인은 [8.11](#811-전사본-패널과-확인할-항목)을 따른다.

### 6.7 설정
- 머리는 다른 화면과 같다("← 홈으로", 세리프 `display-m` "설정"). 왼쪽 탭 목록(넓은 창에서는 스크롤해도 따라오고, 좁은 창에서는 내용 위 한 줄). 선택 표시는 `sunken` 바탕 하나가 탭 사이를 `spring.snappy`로 미끄러진다(`layoutId`).
- 탭마다 Pretendard `title` 제목, `ink-2` 한 줄 설명, 그 아래 묶음. 묶음은 `surface` 바탕 하나(테두리·그림자 없음, 16px 모서리)이고 행은 가는 `line`으로 나눈다. 행은 왼쪽에 레이블과 도움말(`label` 크기, 굵기 400, `ink-2`), 오른쪽에 조작(288px)이다. 좁은 창에서는 조작이 레이블 아래로 간다. 묶음에 속하지 않는 안내(알림, 헤드폰)는 묶음 아래 작은 `ink-2` 글자다. 칸마다 카드를 두지 않는다.
- 전사: 모델 묶음(모델, 파일별 상태와 받는 동안의 진행 막대, 다운로드·취소·직접 가져오기, 다운로드 주소)과 처리 묶음(백엔드, `gpu_failed` 안내, 용어집). 백엔드는 선택 목록 대신 분할 선택(자동 / GPU / CPU)이다: `sunken` 홈 안에서 흰 손잡이가 미끄러진다.
- 요약(LLM): 연결은 행 목록이다. 행에는 이름, 호스트, 글자 꼬리표 "로컬"/"클라우드"(색만으로 알리지 않는다), 기본 연결이면 브랜드색 "기본"이 있고, 누르면 그 자리에서 펼쳐져 고친다. 높이는 `layout`으로 움직이고 CSS로 높이를 움직이지 않는다. 마지막 행이 이름 입력과 "연결 추가"다. 기본 LLM과 "새 회의를 기본으로 로컬에서 요약"은 그 아래 묶음의 행이다.
- Slack(2026-10-20): 행 하나. 왼쪽은 워크스페이스 이름(로그인 전에는 "Slack 계정")과 한 줄 안내, 오른쪽은 작은 outline 버튼 하나다: "Slack으로 로그인"(Slack 로고, 회사 색이 아니라 Slack 자기 색), 브라우저를 기다리는 동안 "취소", 로그인했으면 "로그아웃". 설정이 아니라 바로 일어나는 일이라 저장 막대에 세지 않는다. 회의 문서의 보내기 막대는 로그인 전에는 "Slack 로그인하기" 링크, 뒤에는 채널 선택(비공개 채널은 `ink-2` 자물쇠)이다.
- 스위치 손잡이는 `spring.snappy`(motion)로 움직인다.
- 테스트(ONB-03): 오디오 탭의 마이크·시스템 오디오 행에 테스트 줄을 둔다. 작은 outline 버튼("테스트") 옆 한 줄의 `ink-2` 글자가 하는 일, 도는 동안 할 일, 결과를 차례로 보인다. 결과는 아이콘이 상태를 싣고(통과 체크 `ok-line`, 실패 원 안의 느낌표 `danger-line`) 글자에는 상태색을 쓰지 않는다. 마이크 테스트 동안만 버튼 옆에 가는 가로 레벨 막대(`brand`, 6px, `sunken` 홈)가 뜬다. 막대는 끝이 각진 채 `scaleX`로 늘고, 둥근 모서리는 홈이 자른다.
- 저장 버튼은 바뀐 내용이 있을 때만 아래 스택(보내기 막대 자리, 독 위)에 흰 알약으로 떠오른다("저장 안 한 변경 3개 · 되돌리기 · 저장"). 저장하면 같은 알약이 체크와 "저장했습니다"로 바뀌고 잠시 뒤 내려간다.
- 1.1.0: 기본 전사 언어 행과 언어 판별 모델 행은 [8.9 설정 행](#89-설정-행), 모델 받기 문구는 [8.10 받기 문구](#810-받기-문구)를 따른다.

- 왼쪽 아래 패널에서 시나리오(빈 홈 / 여러 상태 / 녹음 중 / 설정 없음)를 고르면 고정 데이터를 처음 상태로 되돌리고 앱을 다시 띄운다. "GPU 경고", "종료 확인"은 Rust가 스스로 보내는 이벤트를 흉내 내 배너와 대화상자를 띄운다.

**0단계에서 정한 것**
- 토큰 이름: 이 문서의 `accent`는 Tailwind에서 `primary`(shadcn 컴포넌트)와 `brand`(우리 코드)다. Tailwind의 `accent`는 shadcn 뜻 그대로 hover 바탕(= `sunken`)으로 남긴다. `accent-press`, `accent-tint`와 나머지 색은 이 문서 이름 그대로다.
- 글자는 `font-display text-display-m`처럼 크기 토큰(줄 높이·자간·굵기 포함)과 글꼴을 따로 쓴다. 모서리는 `rounded-control`(10px)·`rounded-float`(16px)·`rounded-full`, 본문 폭은 `max-w-doc`·`max-w-home`·`max-w-wide`다(녹음 화면은 760px).
- 세리프 두 폰트에 `tnum`이 없어 타이머는 Pretendard 고정폭 숫자로 쓴다. 이탤릭 숫자는 바뀌지 않는 숫자에만 썼다(3판에서 뺐다).
- 버튼 눌림은 CSS(`motion-safe:active:scale-[0.97]`, 120ms, `transform`만)로, 스위치 손잡이는 CSS 전환으로 했다. `spring.snappy`로 바꾸는 것은 3단계다.
- 화면 전환은 `AnimatePresence`의 `popLayout`이다: 나가는 화면은 흐름에서 빠져 겹쳐 사라지고(들어오는 시간의 65%), 들어오는 화면은 바로 자리를 잡아 레이아웃이 흔들리지 않는다.

**1단계에서 정한 것**
- 제목 공유 전환(6.1)은 회의 문서와 함께 2단계에서 한다. 지금 문서 쪽 제목이 처리 중·검토 두 화면에 나뉘어 있어서다. 홈 행의 제목은 자기 요소에 따로 두어 `layoutId` 래퍼를 바로 씌울 수 있다. 독 바탕과 녹음 화면 파형의 `layoutId` 이음(6.2)도 하지 않았다. 독은 녹음 화면에서 숨는다.
- 화면 전환 방향은 `AnimatePresence`의 `custom`으로 넘긴다(`{ dir, instant }`). 홈으로 가면 뒤로, 그 밖은 앞으로다. 단축키가 일으킨 전환은 `instant`라 움직이지 않는다(5의 "키보드로 한 동작"). 녹음 종료는 `stop_recording`의 응답과 `recording://stopped` 중 먼저 온 쪽이 그 표시를 가져간다. 독의 모양 변화는 상태 변화라 단축키로 시작해도 그대로 움직인다.
- 독의 "처리 중 N"은 실행 중 + 대기다(트레이의 "처리 중"과 같은 셈). 지금 일 한 줄은 줄 맨 앞 회의(실행 중 먼저, 그다음 대기 순서)이고, 제목이 아직 없으면 "14:00 회의"로 부른다. 전사 중이면 "전사 42%"(퍼센트는 MotionValue 글자), 요약 요청이 둘 이상이면 "요약 2/3", 셀 것이 없으면 원 대신 4분의 1 호가 돈다(`motion-safe:`). 대기만 있으면 빈 원과 "대기 중"이다.
- 2차(같은 날, 리뷰와 시각 점검 뒤): 첫 등장은 앞의 8행까지만 기다린다(마지막도 280ms 안). 녹음 화면은 한 열로 가운데 모아 창 높이의 가운데에 둔다. 파형은 줄마다 3px 막대 48개(24대역을 가운데에서 바깥으로), 범례는 파형 아래 가운데, 타이머는 "12:43"(한 시간부터 "1:02:03")에 Pretendard 300이다(`display-xl` 굵기 300). 첫 화면도 창 높이의 가운데다. 설정 줄은 짧은 링크("전사 모델 받기", "LLM 연결", "Slack 채널 연결")이고 "전사 설정"은 받는 중·실패일 때만 흐리게 붙는다. 조사는 "(으)로" 대신 `josa`로 고른다. 반짝임은 글자 상자 밖으로 나가지 않는다(`overflow-hidden`). `⌘R`을 설정 화면에서 누르면 저장하지 않은 입력을 지키려고 화면을 옮기지 않고 독만 녹음을 보인다. 단축키는 열린 선택 목록·메뉴에서도 쉰다. 스스로 끝난 녹음은 목록이 따라올 때까지 독이 "전사를 시작합니다"로 잇고, 독의 "종료"를 누르면 포커스가 알약으로 옮겨 모양이 바뀌어도 남는다. 단축키 표시는 불투명도 70%(종이 위 4.5:1 이상)다.
- 독 미니 파형 12막대는 24대역을 넷씩 묶은 6단계를 가운데가 낮은 대역이 되게 좌우로 펼친 것이다(마이크와 시스템 중 큰 값, `rec` 색, 끝이 각진 막대에 `scaleY`). 경과 시간의 첫 값은 회의의 `created_at`에서 채워, 홈으로 돌아올 때마다 숫자가 0부터 굴러오지 않는다.
- 녹음 종료를 누르면 독은 목록이 녹음 끝을 보일 때까지 "전사를 시작합니다"다. 시작·종료는 `App.tsx` 한 곳이 맡고(홈, 첫 화면, 독, 녹음 화면, 단축키가 같이 쓴다) 실패는 앱의 닫을 수 있는 경고 배너로 보인다.
- 상태 변화는 독 아래 숨은 `role="status"` 한 줄이 한 번씩 말한다: "녹음을 시작했습니다", "녹음을 마쳤습니다. 처리를 시작합니다", "처리를 시작했습니다", "처리를 마쳤습니다". 독은 첫 목록을 읽은 뒤에 붙어서, 앱을 연 순간의 상태는 말하지 않는다.
- 지금 할 일: 녹음 중, 처리 중·대기(다시 시도해 줄에 선 실패 포함), 검토 대기(음성 없음 포함), 실패, 중단된 녹음. 새 버전 앱의 회의는 읽기만 하므로 날짜 묶음에 "새 버전 앱의 회의"로 둔다. 지금 할 일 안의 다른 날 회의는 시각 아래 "어제"나 "10월 12일"을 붙인다. 묶음 제목 옆 개수는 이탤릭 숫자였다(3판에서 Pretendard 보통 굵기로 바꿨다).
- 행 동작: 녹음 중 → "녹음 화면으로", 중단된 녹음 → "처리 계속"(옆에 "삭제", 열 화면이 없어 행 자체는 누르지 않는다), 검토 대기 → "검토하기", 전사 실패 → "다시 시도", 요약 실패 → "요약 다시 실행"(연결을 고르는 회의 문서를 연다, SUM-07). 처리 중·대기·보냄·전송 안 함·전사 완료에는 없다. 보낸 회의는 "#회의록으로 보냄", 제목이 없는 행은 `ink-2`의 "42분 녹음"(녹음 중이면 "녹음 중인 회의")이다. 전사 중 행은 "전사 42% · 약 3분 남음"과 행 아래 1px 진행선이다.
- 첫 화면은 회의가 하나도 없을 때만이다. 목록을 읽기 전에는 홈 본문을 비워 첫 화면이 일반 홈 앞에서 깜빡이지 않게 하고, 읽기에 실패하면 일반 홈(녹음 시작 있음)을 보인다. 연출은 녹음 버튼 둘레에 엇갈려 퍼지는 원 둘(2.8초, `animate-ring`)이다.
- 행이 떠오르는 연출은 앱을 실행한 뒤 첫 홈에서 한 번만 한다(모듈 변수). 홈은 화면이 바뀔 때마다 새로 마운트되기 때문이다. 첫 등장 뒤 다른 묶음으로 옮겨 붙는 행도 움직이지 않는다.
- 단축키: `⌘R` 녹음 시작, `⌘.` 녹음 종료(Windows는 `Ctrl`). 키는 `e.code`로 본다(한글 입력 중에도 `KeyR`). 입력란·대화상자에서는 아무것도 하지 않지만 `preventDefault`는 늘 해 웹뷰가 새로 고쳐지지 않는다. 녹음 중이거나 시작 중이면 `⌘R`은 무시한다. 버튼에는 `aria-keyshortcuts`와 화면용 `⌘R` 표시(`aria-hidden`)를 둔다. macOS 앱 메뉴에는 두 키와 겹치는 항목이 없다. Windows WebView2의 자체 `Ctrl+R`이 페이지의 `preventDefault`보다 먼저 도는지는 확인하지 못했다(Windows 미검증).

**2단계에서 정한 것**
- 처리 중·검토 화면은 `screens/Meeting.tsx` 하나다(경로 `{ name: "meeting", id }`). 홈 행, 독, 알림, 녹음 종료가 모두 이 화면을 열고, 요약이 끝나도 화면을 옮기지 않는다. 머리는 목록의 회의로 첫 렌더부터 그린다(제목이 행에서 미끄러져 올 수 있게).
- 메타 줄의 SUM-07은 "회사 클라우드로 보내 요약함" / "이 PC에서 Ollama로 요약함"이고, 녹음자는 지금 설정의 이름이다(회의마다 저장하지 않는다). 보낸 시각은 회의 날과 같으면 시:분만, 다르면 날짜도 쓴다.
- 제목 입력란은 한 줄 `textarea`다(6.6의 "입력란"). 44px 세리프에서 긴 한글 제목이 가로로 밀리지 않고 줄바꿈되게 하려는 것이다. Enter는 줄을 바꾸지 않고, 붙여 넣은 줄바꿈은 캐럿을 옮기지 않고 공백이 된다. WebKit에 `field-sizing`이 없어 제목과 본문 모두 거울 층이 높이를 잡는다. 형광펜의 바깥 2px은 `box-shadow`라 글자 자리를 옮기지 않는다. 세리프의 높은 글자가 넘치지 않게 둘 다 아래 4px 여백을 두고, 그래도 textarea가 스스로 스크롤하면 0으로 되돌린다.
- 입력란의 포커스 표시는 글 둘레 윤곽선 대신 2px 브랜드 선이다: 제목은 아래에서 왼쪽부터 펼쳐지고(200ms, `motion-safe:`), 본문은 왼쪽 여백에 선다.
- 단계 줄은 대기·처리 중뿐 아니라 실패와 LLM 없이 멈춘 상태에도 둔다(어디서 멈췄는지). 처리 장치(GPU/CPU)는 단계 줄 아래 한 줄 끝에 붙인다. 진행 값은 숨은 `progressbar`가 말한다. 뼈대는 대기·처리 중에만 있고, 반짝임은 막대마다 지나간다(종이 위를 지나는 띠는 얼룩처럼 보였다).
- 요약이 도착하는 연출은 열어 둔 동안 요약 전 상태에서 `review`로 바뀔 때만이다. `revealVariants`·`sectionVariants`(`lib/motion.ts`)로 문서 보기의 섹션마다 40ms, 앞 8개까지. 이미 요약된 회의를 열 때는 움직이지 않는다. 연출 동안은 읽기 전용이고("고치기"는 자리만 잡고 보이지 않는다) 끝나면 같은 문서를 고칠 수 있다. 문서와 편집기를 바꾸는 `AnimatePresence`에 `initial={false}`를 두지 않는다: 그 안의 이 연출까지 막는다. 첫 등장은 `instant`라 어차피 움직이지 않는다.
- 보내기 막대는 `App.tsx`의 아래 스택(`fixed` + `layoutRoot`, 독과 한 컨테이너)에 포털로 들어간다. 화면 안에 `fixed`로 두면 화면 전환의 transform이 막대를 끌고 다닌다. 같은 이유로 전사본 패널은 `body`에 포털로 둔다. 둘 다 포털이라 화면의 `inert`가 닿지 않아 각자 `Present`로 감싸고, 화면이 나가기 시작하면 함께 나간다. 채널 선택은 늘 보이고(녹음자의 채널은 여럿이다) 버튼도 채널 이름을 싣는다(SND-04). 보낸 뒤 버튼은 같은 자리에서 체크와 "#회의록으로 보냄"이 되고 막대는 그 방문 동안 남는다. 종이비행기는 버튼 안에서 transform으로만 날아간다.
- 더보기는 shadcn `dropdown-menu`를 쓰는 부분만 남겨 우리 토큰으로 다시 입혔다(`rounded-float`, `shadow-float`, 키보드 포커스의 안쪽 2px 링, 삭제 아이콘만 `danger-line`). 메뉴에서 연 확인 창이 닫히면 포커스는 ⋯로 돌아온다.
- 제목 공유 전환: `layoutId`는 감싼 요소에, `layout="position"`. `spring.gentle` 대신 300ms `ease.out` tween이다(`titleMove`, 매일 보는 화면의 상한). 홈 행은 여는 버튼(행, "검토하기"·"요약 다시 실행")에 포인터가 눌린 행과 클릭으로 돌아온 회의의 행만 600ms(`TITLE_GLIDE_MS`) 동안 `layoutId`를 갖는다(모든 행이 가지면 다른 묶음으로 옮겨 붙는 행의 제목만 미끄러진다. "다시 시도"를 누르는 것은 열기가 아니다). Motion은 `layoutId`를 요소를 만들 때만 읽어, 행 제목은 `layoutId`가 바뀌면 새로 만든다(이게 없으면 앞으로 가는 미끄러짐이 일어나지 않았다). 돌아오는 미끄러짐은 그 행에서 온 회의만이다(독·알림으로 연 회의의 행은 화면 아래에 있을 수 있다). 문서 제목은 도착한 뒤 600ms와 나갈 때만 미끄러지고, 메타 줄이 두 줄이 되는 것 같은 다른 자리 이동은 바로다. 키보드로 연 회의, 스크롤된 페이지(화면이 바뀌면 맨 위로 돌아가므로), 움직임 줄이기에서는 하지 않는다. 키보드로 누른 행 열기, 독, "홈으로"는 화면 전환도 움직이지 않는다(5의 "키보드로 한 동작").
- `phase`: 마지막 진행률 이벤트가 실행 중이면 목록 상태와 상관없이 실행 중이다. 전사와 요약 사이에 목록이 `transcribed`를 읽어도 독이 같은 자리에서 깜빡이지 않는다.
- 스프링 MotionValue로 숫자를 따라가는 일(독의 원, 단계 줄의 퍼센트, 글자 수 게이지)은 `common.tsx`의 `useFollow` 하나가 맡는다(움직임 줄이기면 `jump`).
- 2차(같은 날, 리뷰와 시각 점검 뒤): 요약 본문을 읽는 문서로 그린다(6.6, 아키텍처 10.1 "문서 보기"·"고치기"). 줄 파서는 Markdown 라이브러리 없이 `MeetingParts.tsx`의 `parseDoc` 하나이고, 블록마다 원문 줄 번호를 가져 누른 줄로 캐럿을 보낸다. 고치기 버튼은 본문 오른쪽 위에 떠(`float`) 첫 줄이 그 옆을 비켜 간다. 편집 중 캐럿이 보내기 막대·독 아래로 숨지 않게 거울 층에서 캐럿 자리를 재어 올린다(`scroll-padding`은 WebKit의 캐럿 따라가기가 지키는지 확인할 수 없어 쓰지 않았다).
- 리뷰 수정: 전사본 패널은 다른 것이 받은 Esc(`defaultPrevented`)를 받지 않는다. 회의 읽기는 자기 오류만 지운다. 단계 줄은 실행 중 이벤트가 목록보다 앞선다. 저장 표시는 `review`에서만이다. "확인할 항목" 요약은 24px 이상이다. `aria-disabled` 버튼은 눌림 효과가 없고, 보낸 버튼의 이름은 `aria-label`이다. 쓰지 않게 된 `badge`를 지웠다(`tooltip`은 0단계부터 쓰지 않았다).
- 제목 자리의 바뀌는 문장은 `display-l` 크기 그대로 `ink-2`다.

**3단계에서 정한 것**
- 설정 탭의 선택 표시는 `sunken`(3의 "선택된 탭")이고 글자는 `ink-2` → `ink`로 바뀐다. 굵기는 바꾸지 않는다(좁은 창의 가로 탭이 흔들리지 않게).
- 행은 `<label for>`가 조작의 이름이고 도움말은 `aria-describedby`다. 선택 목록의 이름도 행 레이블이다("마이크", "모델", "기본 LLM"). Radix 선택 목록은 `pointerdown`에 열리고 `fieldset`의 막힘을 읽지 않으므로, 저장하는 동안과 읽기 전용에는 자기 `disabled`로 막는다.
- 분할 선택은 숨긴 네이티브 라디오다: 화살표 키로 고르고 묶음의 `fieldset`이 같이 막으며, 포커스 링은 라디오의 레이블에 그린다. `<label for>`는 묶음(`radiogroup`)을 이름 짓지 못하므로 행 레이블을 `aria-labelledby`로 가리키고, 도움말은 다른 행처럼 `aria-describedby`다. 손잡이는 `layoutId`, 키로 고르면 움직이지 않는다.
- 연결 행은 하나만 펼친다. 새로 추가한 행과 저장 검사에 걸린 연결은 펼쳐진다. 이름 문제("이름을 입력하세요", "저장한 뒤 다시 추가하세요")는 위 배너가 아니라 추가 행 아래에 보인다. 저장 오류는 탭 위 배너에 남고, 저장을 누른 창 아래에서 보이도록 배너로 스크롤한다.
- 펼침: 목록 바탕은 `layout`(모서리는 `style`), 행·추가 행·아래 묶음은 `layout="position"`이고 모두 `layoutDependency`(펼친 행과 이름들)가 바뀔 때만 움직인다. 숨겨 둔 탭이 보일 때 행이 0에서 날아오지 않게 하려는 것이다. 행은 불투명해서 내려가는 행이 펼쳐지는 칸을 덮으며 드러낸다. 펼친 칸은 불투명도로 들어오고, 접을 때는 바로 빠지며 아래 행이 올라온다. 키로 열고 닫으면 움직이지 않는다. 스프링은 `spring.gentle`(약 270ms에 멈춘다).
- 스위치 손잡이는 motion `x`(`spring.snappy`)다. Space·Enter로 바꾸면 바로 옮긴다. 쓰이지 않던 `sm` 크기는 지웠다.
- 저장 막대: N은 바뀐 필드 하나씩, 추가·삭제·수정한 연결은 필드가 몇 개 바뀌든 하나씩, 입력한 키 하나씩(공백만 넣은 키도: 저장이 지운다), 키체인에서 아직 지우지 못한 키 하나씩이다. 필드는 저장할 모양으로 비교한다: 용어집은 빈 줄과 앞뒤 공백을 뺀 목록, 녹음자 이름은 앞뒤 공백을 뺀 값, "기본으로 로컬에서 요약"은 로컬 연결이 있을 때만 켜진 값이다. 그래서 저장 때 고쳐 넣는 값은 세지 않는다. 읽기 전용이면 막대가 없고 저장도 하지 않는다. 저장하는 동안에는 누를 때의 N을 그대로 보이며 막대가 남는다: `settings.json`을 쓴 뒤 키체인을 지우고 넣는 동안 초안은 이미 저장본과 같아 N이 0이 되기 때문이다(그 사이 막대가 내려가면 포커스가 페이지로 떨어졌다). "저장했습니다"는 1.5초 남는다.
- 저장하는 동안 막대의 버튼은 `disabled`가 아니라 `aria-disabled`("저장 중…")다. `disabled`는 키보드 포커스를 떨어뜨린다. 입력은 `fieldset`이 막는다. 저장이 끝나 버튼이 사라지면(성공, 되돌리기) 포커스는 페이지가 아니라 지금 탭 버튼으로 간다(좁은 창에서 탭이 화면 밖이면 그리로 스크롤한다). 행을 지우면 포커스는 그 목록의 추가 입력란으로 간다. 대화상자에서 키로 확인한 삭제와 되돌리기는 행을 움직이지 않는다. 같은 저장 오류가 다시 나도 배너를 새로 그려 다시 알리고 그리로 스크롤한다.
- 되돌리기는 마지막 저장 상태로 돌린다(입력한 키 포함). 입력한 키가 있을 때만 묻는다. 키체인에서 못 지운 키는 되돌릴 것이 아니라 남는다(그것만 남으면 되돌리기가 없다).
- 저장하지 않고 떠나면 그대로 버린다(아키텍처 9.3). 떠나기 확인은 넣지 않았다: 화면 전환·`⌘R`·알림 클릭이 모두 거쳐야 해서 작지 않다.
- 마감: 쓰지 않던 `tooltip`과, 설정이 카드를 버려 쓰지 않게 된 `card`를 지웠다. 키보드로 누른 버튼이 화면과 함께 사라지면(홈의 행, "홈으로", 녹음 종료) 포커스는 새 화면의 제목(`h1`, `tabIndex=-1`, 윤곽선 없음)으로 간다. 제목이 아직 없으면(목록을 읽기 전의 홈) 화면 상자가 받는다. 앱을 처음 열 때는 하지 않는다(StrictMode의 두 번 실행에서도: 마지막으로 보인 화면 키와 비교한다). 포커스된 요소가 머리(48px)와 아래 스택(막대 + 독, 148px까지)에 가리지 않게 `html`에 `scroll-padding`(위 64px, 아래 160px)을 둔다. Chromium에서는 포커스 스크롤이 이것을 지키는 것을 확인했고 WebKit은 확인하지 못했다. 회의 편집기의 캐럿은 위로 갈 때도 머리 아래 16px까지 내린다(2단계의 아래 올림과 같은 방식). 선택을 넓힐 때는 움직이는 끝을 잰다(Shift+Up이면 시작).
- 전사 탭의 모델 받기: 받는 동안에는 취소와 진행 막대만 보인다(다운로드·직접 가져오기는 숨는다). 모델 상태를 읽지 못하면 직접 가져오기만 남긴다(ONB-02).
- 미리보기(3단계): "여러 상태"·"녹음 중"은 연결 셋(로컬 하나)과 Slack 로그인(채널 셋, 비공개 하나)이다. 로그인은 2초 뒤 끝나고 그 전에 취소할 수 있다. "설정 없음"은 시나리오를 고를 때 300MB 받아 둔 모델 받기를 이어서 시작해(약 32MB/s) 홈 설정 줄과 전사 탭에서 받는 중을 볼 수 있다. 받지 않은 상태의 "전사 모델 받기"는 "첫 화면"에 있다.

단계마다 기존 Vitest 테스트를 바뀐 구조에 맞게 고치고, 동작 테스트(자동 저장, 전송, 고지, D6·D8)는 그대로 통과해야 한다.

**피드백 반영 (2026-10-16)**
- 세리프는 포인트에만 쓴다. 사용자가 세리프가 너무 많다고 했다: 대부분의 UI는 산세리프가 낫고, 세리프는 화면에 포인트가 될 곳에만 둔다. 세리프로 남긴 곳은 홈 날짜 머리, 화면 제목(`Page`의 `h1`, 예: "설정"), 녹음 화면의 "진행 중인 녹음이 없습니다", 첫 화면 헤드라인, 회의 문서 제목 다섯 곳이다. 날짜 그룹·설정 탭·문서 섹션 제목, 전사본 패널과 대화상자 제목, 홈 행의 시각과 제목, 홈 머리의 요일, 첫 화면 단계 숫자, 워드마크는 Pretendard로 바꿨다. `title`은 이제 Pretendard 제목이라 세리프 때문에 키운 한 칸을 되돌려 18px / 1.4 / 600이다(2).
- 이탤릭은 쓰지 않는다. 남은 이탤릭 숫자가 없어 `400-italic.css`를 빼고 `html`의 `font-synthesis`를 `none`으로 바꿨다(가짜 굵게를 막는 뜻은 그대로다).
- 포인트 색: 회사 `mainBlue`(#5550FF)는 따뜻한 종이 바탕에서 혼자 차갑게 떠 보였다. 전체 톤은 그대로 두고, OKLCH에서 색상각 276°는 지킨 채 채도를 약 40% 낮추고 어둡게 했다(`accent` #4950B0, oklch 0.48 0.15 276). `accent-press`는 #393D95, `accent-tint`는 #E6E8FB다. `mic` 트랙과 트레이의 처리 중 점도 `accent`와 같은 값이다. 대비는 모두 4.5:1 이상이다(3).
- UI 글자에 em dash를 쓰지 않는다. AI가 쓴 글처럼 보인다. 첫 화면과 회의 문서 단계 줄의 구분은 `lucide-react`의 `ChevronRight`(14px, `ink-3`, `aria-hidden`)다. 화면 읽기 프로그램에는 목록 항목으로 나뉘어 읽힌다.
- 헤더: 왼쪽에 회사 로고(SIJE, 인라인 SVG, `currentColor`), 가는 세로 구분선, "회의 요약"(Pretendard)을 둔다. 버튼 이름은 "SIJE 회의 요약"이다. 처리 중에 움직이던 3막대는 헤더에서 뺐다(처리는 독이 보인다). 3막대는 홈 행과 단계 줄의 전사 중 표시로 남는다.

**M6에서 정한 것**
- 테스트는 설정을 바꾸지 않는다. 그래서 초안 밖의 상태이고 저장 막대에 세지 않으며, 저장하지 않은 선택(마이크, Windows 출력 장치)으로 그대로 해 본다. 결과는 그 테스트가 쓴 장치를 기억해, 다른 장치를 고르면 보이지 않는다(도는 중에 바꿔 결과가 늦게 와도). 도는 중에 녹음이 시작돼 멈춘 테스트는 "녹음이 시작되어 테스트를 멈췄습니다"라, 녹음이 끝난 뒤에도 아직 녹음 중처럼 읽히지 않는다. 오디오 테스트는 앱 전체에서 한 번에 하나라(Rust가 "이미 테스트 중입니다"로 거부한다), 하나가 도는 동안 다른 오디오 버튼도 `aria-disabled`로 쉰다. 그 거부가 보이는 것은 테스트 중에 설정을 나갔다 다시 온 때뿐이다. 미리보기도 같은 거부를 흉내 낸다.
- 오디오 테스트는 행 아래 줄이다(행의 `below`). 시스템 오디오 테스트를 따로 "시스템 오디오" 행으로 두면 같은 이름의 행이 둘이 되어, 있던 시스템 오디오 행 아래에 붙였다. 하는 일("짧은 소리를 재생해 앱에 들리는지 확인합니다", "5초 동안 마이크 소리를 들어 봅니다")은 행 도움말이 아니라 버튼 옆 줄에 두고, 누르면 그 자리가 할 일과 결과로 바뀐다.
- 버튼 이름은 "마이크 테스트", "시스템 오디오 테스트"(`aria-label`)이고 보이는 글자는 "테스트"다. 도는 동안 글자는 "테스트 중…", "보내는 중…"이고 이름도 "마이크 테스트 중"처럼 따라 바뀐다(보이는 글자가 이름 안에 있게, WCAG 2.5.3). 도는 동안과 녹음 중에는 `disabled`가 아니라 `aria-disabled`라 포커스가 남는다(3단계와 같은 이유). 녹음 중(시작 중 포함)에는 오디오 버튼만 쉬고, 묶음 아래 `role="status"` 한 줄이 "녹음 중에는 테스트할 수 없어요"를 말한다. 줄마다 두면 녹음이 시작될 때 같은 말을 두 번 한다. 도는 중에 녹음이 시작되면 Rust가 테스트를 멈추고 그 오류가 결과 자리에 보인다. Slack 테스트는 녹음과 상관없다.
- 줄의 글자는 `role="status"` 하나라 바뀔 때마다 한 번 말한다. 처음 보이는 하는 일은 말하지 않는다. 마이크 레벨은 `role="meter"`("마이크 입력 레벨")이고 25Hz 값은 React 상태를 거치지 않고 `aria-valuenow`와 `transform`에 바로 쓴다(5).
- OS 설정 목록을 가리키는 안내는 앱을 번들 이름 `'meeting-summarizer'`로 부른다(macOS의 "개인정보 보호 및 보안 > 마이크", "화면 및 시스템 오디오 녹음", 일반 탭의 알림 안내). OS가 그 이름으로 보이기 때문이다. 화면의 제품 이름 "회의 요약"(헤더, 트레이)은 그대로다.
- 시스템 오디오 실패 안내에 출력 음량을 넣지 않는다. tap과 루프백은 음량 전의 소리를 들을 가능성이 커(실기기 미확인) 틀린 안내가 될 수 있다. macOS는 권한, Windows는 고른 출력 장치만 말한다.
- 결과 말투는 짧은 해요체다("소리가 들어와요", "시스템 오디오가 잡혀요"). 전송처럼 일이 끝난 것은 "보냈습니다. Slack 채널을 확인하세요"다. Rust가 준 오류는 그대로 보인다.
- 미리보기: 시스템 오디오 테스트는 1초 뒤 통과, 마이크 테스트는 5초 동안 말소리 모양의 레벨을 보낸 뒤 통과다.

## 8. 1.1.0 화면 명세 (M6.7)

[M6.7 계획](plans/2026-11-03-windows-and-workflow.md) 5.3~5.7절의 화면을 화면×상태로 모은 표다(2026-11-03). 일시정지, 녹음 파일 저장, 여러 채널 전송, 전사 언어(여러 개 고르기, 다른 언어로 다시 전사, 혼합 언어 회의)를 다룬다. 동작은 계획에 있고, 이 장은 보이는 것만 적는다. 문구는 계획과 같다. 둘 중 하나를 고치면 다른 쪽도 고친다. 미리보기 시나리오와 Vitest는 이 표의 행을 따른다(계획 5.7-14~16).

- 열은 상태, 문구, 조작, 아이콘, 접근성이다. "-"는 없음, "지금 그대로"는 1.0.3까지의 화면을 바꾸지 않는다는 뜻이다. 아이콘은 모두 `lucide-react`다.
- 새 버튼은 기존 Button 크기(ghost sm 이상)와 포커스 링 토큰을 쓴다. 상태 문구는 조용한 `caption`이고 경고색을 쓰지 않는다. 새 카드는 두지 않는다.
- 최소 창 720×600과 글자 크기 125%에서 겹치는 것이 없어야 한다(계획 5.7-17).
