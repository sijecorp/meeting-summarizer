# 설치 안내

회의를 녹음하고 요약해서 Slack으로 보내 주는 앱입니다. 설치는 5분이면 끝납니다.

## 설치 파일 받기

<OneDrive 링크>에서 내 컴퓨터에 맞는 파일 하나를 받습니다. 저장소에 접근할 수 있으면 [GitHub Releases](https://github.com/sijecorp/meeting-summarizer/releases/latest)에서 받아도 됩니다.

| 컴퓨터 | 파일 |
|---|---|
| Mac (Apple 실리콘: M1 이후, macOS 14.6 이상) | `meeting-summarizer_버전_aarch64.dmg` |
| Windows 10(1809 이상)/11 (64비트) | `meeting-summarizer_버전_x64-setup.exe` |

Intel 칩 Mac은 지원하지 않습니다. Mac의 칩은 Apple 메뉴 > 이 Mac에 관하여에서 볼 수 있습니다.

Windows 10은 버전 1809(2018년 10월 업데이트) 이상이어야 합니다. 그 전 버전에서는 앱이 열리지 않습니다. 버전은 시작 > 설정 > 시스템 > 정보의 "Windows 사양"에서 볼 수 있습니다.

앱은 처음 쓸 때 전사 모델과 요약 모델(합쳐 약 3.4 GB)을 받습니다. 받는 동안 디스크에 1 GB가 더 남아 있어야 하므로, 처음에는 약 4.4 GB의 빈 공간이 필요합니다. 모자라면 앱이 몇 GB가 더 필요한지 알려 줍니다.

## Mac

1. 받은 `.dmg` 파일을 엽니다.
2. 열린 창에서 앱 아이콘을 "응용 프로그램" 폴더로 끌어다 놓습니다.
3. 응용 프로그램 폴더에서 앱을 엽니다. 처음에는 "악성 코드가 없음을 확인할 수 없습니다"라는 경고가 뜨고 열리지 않습니다. "완료"를 누릅니다. "휴지통으로 이동"은 누르지 마세요.
4. Apple 메뉴 > 시스템 설정 > 개인정보 보호 및 보안으로 갑니다. 아래쪽 "보안" 부분에 있는 "그래도 열기"를 누르고, 다시 뜨는 창에서도 "그래도 열기"를 누른 뒤 Mac 로그인 암호를 넣습니다.
   - 이 버튼은 앱을 열려고 한 뒤 1시간쯤만 보입니다. 보이지 않으면 3번부터 다시 합니다.
   - 사내에서만 쓰는 앱이라 Apple의 검사를 받지 않아서 생기는 단계입니다. 처음 한 번만 하면 됩니다.
5. 처음 녹음을 시작하면 권한 요청이 두 번 뜹니다. 둘 다 "허용"을 누릅니다.
   - 마이크: 내 목소리를 녹음합니다.
   - 시스템 오디오 녹음: 화상 회의 상대방의 목소리를 녹음합니다.

실수로 "허용 안 함"을 눌렀다면 시스템 설정 > 개인정보 보호 및 보안에서 "마이크"와 "화면 및 시스템 오디오 녹음"에 들어가 meeting-summarizer를 켜고, 앱을 종료했다가 다시 엽니다.

앱을 종료하려면 화면 위쪽 메뉴 막대의 앱 아이콘을 누르고 "종료"를 고릅니다. 창을 닫으면 앱은 메뉴 막대에 남아 있습니다.

## Windows

1. 받은 `-setup.exe` 파일을 엽니다.
2. "Windows의 PC 보호" 창이 뜨면 "추가 정보"를 누르고 "실행"을 누릅니다. 사내에서만 쓰는 앱이라 뜨는 창입니다.
3. 설치 프로그램의 안내대로 "다음"과 "설치"를 누릅니다. 관리자 권한은 필요 없습니다. 내 계정에만 설치됩니다.
4. 설치가 끝나면 시작 메뉴에서 meeting-summarizer를 엽니다.

드물게 WebView2라는 구성 요소가 없는 PC에서는 설치 중에 이것을 함께 설치하며, 이때 관리자 암호를 물을 수 있습니다. 암호를 모르면 IT 담당자에게 요청하세요.

앱을 종료하려면 작업 표시줄 오른쪽 아래(숨겨진 아이콘 ^ 안에 있을 수 있습니다)의 앱 아이콘을 오른쪽 클릭하고 "종료"를 고릅니다. 창을 닫으면 앱은 그곳에 남아 있습니다.

## Slack 연결

요약을 Slack으로 보내려면 한 번 로그인합니다. 녹음과 요약은 로그인하지 않아도 됩니다.

1. 앱 오른쪽 위 톱니(설정) > Slack > "Slack으로 로그인"을 누릅니다.
2. 브라우저가 열리면 회사 워크스페이스를 확인하고 "허용"을 누릅니다. "Slack 로그인을 마쳤습니다"가 보이면 브라우저 탭을 닫습니다.
3. 앱의 Slack 탭에 워크스페이스 이름이 보이면 끝입니다.

요약을 검토한 뒤 회의 문서 아래의 보내기 막대에서 채널을 고르고 보냅니다. 메시지는 내 이름으로 올라갑니다. 목록에는 내가 들어가 있는 채널만 나오므로, 보낼 채널에 먼저 들어가 둡니다. 앱에서 Slack을 30일 동안 쓰지 않으면 로그인이 끝나고, 앱이 다시 로그인하라고 알려 줍니다.

## 새 버전으로 업데이트

앱이 스스로 업데이트하지 않습니다. 새 버전 소식이 오면 같은 링크에서 새 설치 파일을 받아 위와 같은 방법으로 설치합니다. 회의 기록과 설정은 그대로 남습니다.

녹음 중이거나 회의를 처리하는 중에는 업데이트하지 마세요. 먼저 앱을 종료합니다.

요약 모델이 들어간 버전으로 업데이트하기 전에, 설정 > 요약(LLM)에 이름이 `builtin`이나 "이 PC"인 연결이 있으면 다른 이름으로 바꾸고 저장합니다. 새 버전은 이 두 이름을 이 PC 요약에 쓰므로, 그런 이름의 연결은 요약에 쓰이지 않고 이름을 바꿀 때까지 설정을 저장할 수 없습니다.

- **Mac**: 새 앱을 응용 프로그램 폴더로 끌어다 놓고 "대치"를 누릅니다. 새 버전도 처음 열 때 위 3~4번(그래도 열기)을 한 번 더 합니다. 업데이트 뒤 처음 Slack으로 보내거나 API 키를 쓸 때 "키체인에 저장된 정보를 사용하려고 합니다" 창이 뜨면 Mac 로그인 암호를 넣고 "항상 허용"을 누릅니다.
- **Windows**: 새 `-setup.exe`를 실행하면 기존 버전 위에 설치됩니다.

요약 모델이 들어간 버전으로 업데이트하면 달라지는 점:

- 업데이트 전에 설정 > 요약(LLM)의 기본 LLM이 "선택 안 함"이었다면, 새 버전에서는 "이 PC"로 보이고 저장한 첫 연결이 아니라 이 PC에서 요약합니다. 계속 그 연결로 요약하려면 기본 LLM에서 그 연결을 고르고 저장합니다.
- 기본 LLM이 "이 PC"이면 홈의 "모델 받기"가 전사 모델과 함께 요약 모델(2.5 GB)도 받습니다. 요약 모델을 다 받기 전에는 전사를 마친 회의가 요약을 기다리고, 다 받으면 저절로 요약합니다. 받는 동안 디스크에 약 3.5 GB(요약 모델 + 1 GB)의 빈 공간이 있어야 합니다.
- 기본 LLM이 클라우드 연결이면 지금처럼 그 연결로 요약하고 요약 모델은 받지 않습니다. 필요하면 설정 > 요약(LLM)에서 따로 받습니다.
- 연결을 추가해도 기본 LLM은 바뀌지 않습니다.
- 사내 미러는 `resolve/<커밋>/` 경로를 넘겨야 합니다. `resolve/main/`만 넘기던 미러에서는 새로 받는 모델이 받아지지 않습니다(아래 "관리자용: 모델 사내 미러").
- Windows에서는 백신이 새 버전의 요약 엔진(`llama-server.exe`)을 다시 막을 수 있습니다. 아래 "회사 PC에서 막힐 때"를 봅니다.

**Mac에서 업데이트 뒤 소리가 녹음되지 않을 때**: Mac은 새 버전을 다른 앱으로 볼 수 있어서 권한을 다시 받아야 할 때가 있습니다.

1. 시스템 설정 > 개인정보 보호 및 보안 > 마이크에서 meeting-summarizer를 껐다가 다시 켭니다.
2. 같은 곳의 "화면 및 시스템 오디오 녹음"에서도 meeting-summarizer를 껐다가 다시 켭니다. 목록에서 골라 아래 "-" 버튼으로 지워도 됩니다. 그러면 다음 녹음 때 권한 요청이 다시 뜹니다.
3. 앱을 종료했다가 다시 엽니다.

## 지우기

- **Mac**: 앱을 종료하고, 응용 프로그램 폴더에서 meeting-summarizer를 휴지통으로 옮깁니다.
- **Windows**: 앱을 종료하고, 설정 > 앱 > 설치된 앱(Windows 10은 앱 및 기능)에서 meeting-summarizer를 찾아 "제거"를 누릅니다. 회의 기록까지 지우려면 제거 창에서 "애플리케이션 데이터 삭제하기"를 고릅니다.

앱만 지우면 회의 기록과 받아 둔 모델이 남아 있어서, 다시 설치하면 회의가 그대로 보이고 모델도 다시 받지 않습니다.

## 회사 PC에서 막힐 때

요약은 앱과 함께 설치되는 요약 엔진(`llama-server`)이 이 PC에서 합니다. 서명이 없는 실행 파일이라 백신이나 회사 보안 프로그램이 막을 수 있습니다. 막히면 회의 문서에 "이 PC 요약 엔진을 실행할 수 없습니다"와 실행 파일 경로가 보입니다. 그 문구와 아래 내용을 IT 담당자에게 보내 예외를 요청합니다. 기다리는 동안 다른 연결이 있으면 회의 문서의 "요약 다시 실행"에서 그 연결을 고르면 됩니다.

IT 담당자용:

| 항목 | Mac | Windows |
|---|---|---|
| 요약 엔진 | `/Applications/meeting-summarizer.app/Contents/MacOS/llama-server` | `%LOCALAPPDATA%\meeting-summarizer\llama-server.exe` |
| 같은 폴더의 파일 | 앱 실행 파일 `meeting-summarizer` | 앱 실행 파일 `meeting-summarizer.exe`, `vulkan-1.dll` |
| 엔진이 읽는 요약 모델 | `~/Library/Application Support/com.sije.meeting-summarizer/models/` | `%LOCALAPPDATA%\com.sije.meeting-summarizer\models\` |
| 로그(`app.log`, `llama-server.log`) | `~/Library/Logs/com.sije.meeting-summarizer/` | `%LOCALAPPDATA%\com.sije.meeting-summarizer\logs\` |

- Windows 경로는 기본 설치 폴더입니다. 설치할 때 폴더를 바꿨으면 그 폴더이고, 앱의 오류 문구에 실제 경로가 나옵니다.
- 앱이 자기 실행 파일을 `--llm-supervisor` 인자로 한 번 더 띄우고, 그 프로세스가 `llama-server`를 실행합니다.
- `llama-server`는 이 PC 안(`127.0.0.1`)에서만 연결을 받고 밖과 통신하지 않습니다. 실행할 때마다 새 키를 써서 다른 계정이나 브라우저에서는 쓸 수 없습니다.
- 새 버전마다 실행 파일이 바뀝니다. 파일 해시로 예외를 두면 업데이트 뒤 다시 막히므로 폴더 경로로 두는 편이 낫습니다.
- Windows에서 `vulkan-1.dll`이 격리되면 앱이 열리지 않습니다.
- 로그 폴더는 앱의 설정 > 일반 > "로그 폴더 열기"로도 열 수 있습니다.

## 관리자용: 설치 파일 만들기

설치 파일은 GitHub Actions의 `build` 워크플로(`.github/workflows/build.yml`)가 만듭니다. Mac은 Apple Developer 계정 없이 임시 서명(ad-hoc)만 하므로 위의 "그래도 열기" 단계가 필요합니다.

1. 새 버전이면 먼저 `src-tauri/tauri.conf.json`의 `version`을 올려 master에 push합니다. 파일 이름에 이 버전이 들어갑니다.
2. 워크플로를 실행합니다. 둘 중 하나입니다.
   - 저장소의 Actions 탭 > 왼쪽 목록의 build > "Run workflow" > 브랜치 master > "Run workflow"
   - 버전 태그 push: `git tag v1.0.0 && git push origin v1.0.0`
3. 태그로 실행했으면 두 OS의 빌드와 검사가 모두 통과한 뒤 그 태그의 GitHub Release가 만들어지고 `.dmg`와 `-setup.exe`가 붙습니다(저장소 첫 화면 오른쪽 "Releases"). Release 설명은 `docs/releases/<태그>.md`이고, 없으면 GitHub가 커밋으로 만듭니다. 그래서 태그를 push하기 전에 그 파일을 써 둡니다. 수동 실행은 Release를 만들지 않으니, 그 실행 페이지 아래쪽 "Artifacts"에서 `meeting-summarizer-macos-arm64`와 `meeting-summarizer-windows-x64`를 받습니다(zip이니 풀어서 꺼냅니다).
4. Release가 만들어지면 두 파일이 Slack 채널에도 올라가, 동료들은 GitHub 권한 없이 Slack에서 바로 받습니다(아래 설정). 비공개 저장소의 Release는 저장소 접근 권한이 있는 사람만 받을 수 있습니다. 그 채널에 없는 사람에게는 두 파일을 OneDrive 공유 폴더에 올려 링크와 이 문서를 알립니다.

- Slack 업로드 설정: https://api.slack.com/apps 에서 앱의 Slack 로그인용 앱([slack-app.md](slack-app.md))과 별도로 새 앱을 만들고, OAuth & Permissions > Bot Token Scopes에 `files:write`를 더해 워크스페이스에 설치합니다. Bot User OAuth Token(`xoxb-`)은 저장소 Settings > Secrets and variables > Actions의 `SLACK_BOT_TOKEN`에, 채널 ID(채널 이름 > 정보 맨 아래의 `C`로 시작하는 값)는 `SLACK_CHANNEL_ID`에 넣습니다. 그 채널에서 `/invite @앱이름`으로 봇을 들입니다. 둘 중 하나가 없으면 경고만 남깁니다. 업로드가 실패하면 `slack` 작업만 실패로 표시되고 Release는 그대로입니다. 지난 릴리스를 다시 보내려면 Actions > slack-release > "Run workflow"에 태그(예: `v1.0.3`)를 넣습니다. 태그를 옮겨 다시 빌드해도 한 번 더 올라갑니다.
- Artifacts는 30일 뒤 지워집니다. Release에 붙은 파일은 남습니다.
- 비공개 저장소에서는 macOS 실행 시간이 10배로 계산됩니다. 배포할 때만 실행합니다.
- 실제 서명과 공증을 하려면 Apple Developer 계정을 만든 뒤 워크플로의 주석 처리된 `APPLE_*` 항목을 저장소 Secrets로 채우고 주석을 풉니다. 그러면 "그래도 열기" 단계와 업데이트 뒤 권한 문제가 없어집니다.
